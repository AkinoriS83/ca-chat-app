# 「登録とログイン」仕様

本書は、[開発方針](../development-policy.md)が定める開発の流れのうち、仕様フェーズの成果物です。フェーズ1(MVP)の最初の機能スライスである「登録とログイン」を対象に、対象とするフローの範囲、機能仕様、受け入れ基準を定めます。

本書の前提は次の通りです。

- 対象は、[ユースケース記述](../use-cases.md)の UC-01、UC-02、UC-03、UC-08 と、共通の規則 R-1 である。[ウォーキングスケルトンの仕様](walking-skeleton.md)の仮実装 WS-P1、WS-P2、WS-P3 を、正式実装に置き換える。
- ウォーキングスケルトンの仕様は、本書が改めた箇所を除き、引き続き成り立つ。同仕様の「固定ユーザー」は、「登録を完了した利用者」に読み替える。
- 技術要素は、本書では選定しない(「技術要素の決定」)。画面の構成と操作の手段は、設計で定める。
- 背景と用語は、開発方針、[仮説](../hypothesis.md)、[企画書](../project-plan.md)、ユースケース記述に従う。「秘密」は、認証に用いる秘密を指す。「送信元」は、要求の送信元の、ネットワーク上のアドレスを指す。

本書で付けるIDは、次の通りです。IDは、本書を改訂しても振り直さず、欠番を許します。

| ID | 対象 |
|---|---|
| RL-D1〜 | 本書で判断した事項 |
| RL-01〜 | 受け入れ基準 |

## 目的と完了の姿

目的は、利用者と、ログインと、相手の選択の仮実装を、正式実装に置き換え、操作を行っているのが誰であるかを、システムが確かめられるようにすることです。

完了の姿は、次の通りです。訪問者が、連絡先を確認して登録し、ログインし、相手の識別名を指定して、1on1でテキストをやり取りし、ログアウトできる。ログインしていない人は、登録とログインのほかに、何も操作できない。

## 本書で判断した事項

### RL-D1 本スライスも、ローカルの開発環境に限って動かす

サーバーの待ち受け先は、引き続き、ループバックのアドレスに限ります。設置環境の構築(OPS-1)は、フェーズ1の、設置環境を扱うスライスに送ります。

- 仮のログインがなくなり、WS-D6 の理由は消えます。しかし、通信経路の暗号化の構成が、まだありません。ローカルの開発環境の外で動かすと、秘密と資格が、暗号化されていない経路を通ります(SEC-2)。[仮実装の箇所の一覧](../temporary-implementations.md)が「仮のログインとともに取り除く」としている待ち受け先の制限は、取り除かず、SEC-2 のためのものとして残します。
- 本スライスで設置環境を構築する案は、採りません。認証の実装と、AWS の構成の選定が、1つのスライスに重なり、費用も生じるためです。
- この帰結として、連絡先への案内は、開発者の端末の外へ送りません。設置環境でメールを送信する手段の選定と、到達の確認(企画書「リスク」14)も、送ります。
- SEC と PRV の水準は、動かす環境に依らず、適用することを原則とします。企画書「水準を最初に適用する時点」が、フェーズ1で最初に着手するスライスの受け入れ基準に含めると定めた、特定の機能に属さない水準(SEC-2、SEC-8、PRV-1、PRV-7)も、本スライスの受け入れ基準に含めます(「非機能要件の適用」)。ローカルの開発環境には、実装との兼ね合いで、次の例外を設けます。例外は、設置環境を扱うスライスで解きます。

| 水準 | ローカルの開発環境での例外 | 理由 |
|---|---|---|
| SEC-2 | 経路を暗号化しない。代わりに、ループバックのアドレスの外からの利用を、受け付けない(RL-38) | 企画書 SEC-2 が、ローカルの開発環境を除いている。暗号化の構成は、設置環境の構成とともに選定する |
| SEC-8 | バックアップを取得しない。保管データと、案内を受け取る手段への到達は、開発者の端末の中に限る(RL-38) | バックアップ(OPS-5)は、設置環境の構成に依る |
| PRV-7 | バックアップと、ログの保持期間を定めない。ログに記録する個人データは、一覧に載せる(RL-36) | ローカルの開発環境は、バックアップを取得せず、ログを保管する仕組みを持たない(サーバーは、ログを、標準出力に出力する) |

### RL-D2 ログインは、連絡先と秘密で行う

- 識別名と秘密で行う案は、採りません。識別名は、他の利用者に見せるものであり(D-2)、知っている人が、失敗を重ねて、本人のログインを妨げられます(「上限」)。変更でき、他の人が再び使えるものでもあります(D-1)。連絡先は、本人以外に見せません。
- この帰結として、利用者は、登録に使った連絡先を覚えている必要があります。連絡先を知る人は、同じ妨げを行えます(RL-D5)。

### RL-D3 秘密の条件

規則は、「入力の規則」の通りです。認証の方式は、ADRで定めますが、UC-01 基本フロー 4 が、利用者が秘密を決めて入力すると定めているため、その前提で条件を定めます。

- 長さの下限は、秘密だけで認証する場合に、NIST が求める値です。多要素の認証は、機能スコープになく、採りません。上限は、照合の計算に上限を与えるために設け、NIST と ASVS が、受け付けるべきとする64文字を上回る値とします。
- 文字の種類の組み合わせ(英字と数字を混ぜるなど)と、定期的な変更は、求めません。NIST が、求めてはならないとしています。
- よく使われる秘密の一覧との照合は、NIST と ASVS が求めています。一覧は、設置環境の中に持ちます。漏えいした秘密を照合する外部のサービスは、使いません。秘密に由来する情報を、外部へ送ることになるためです(PRV-3)。この帰結として、一覧にない、漏えい済みの秘密は、受け付けます。
- 秘密は、入力された通りに扱い、文字を置き換えません(ASVS)。NIST は、Unicode の正規化(NFC)を勧めていますが、採りません。この帰結として、同じに見える文字を、異なる並びで入力する環境からは、ログインできないことがあります。
- 出典: NIST SP 800-63B-4 3.1.1.2。OWASP ASVS 5.0.0 6.2.1、6.2.4、6.2.5、6.2.8、6.2.9(2026-11-26 に確かめた)。

### RL-D4 ログイン状態の有効期限と、保つ単位

値は、「ログイン状態」の通りです。

- 有効期限は、ログインからの経過だけで定め、操作によって延ばしません。操作のない時間による期限は、設けません。チャットは、開いたままにして使うものであり、操作と、リアルタイムの接続の、どちらを「操作がある」と見なすかの規則が要るためです。値は、NIST が、最も低い保証の水準で、上限の目安とする日数です(NIST SP 800-63B-4 2.1.3。2026-11-26 に確かめた)。
- ログイン状態は、ブラウザの単位で保ち、同じブラウザのタブが共有します。広く使われているサービスと、同じ単位です。タブごとに持つ案(ADR-013 の形)は、採りません。再読み込みのたびに、ログインが要るためです。
- UC-02 A1 と UC-03 の「端末」は、ログイン状態については、ブラウザと読み替えます。ログイン状態を、端末(タブ1つ)ごとに分けないため、ログアウトは、同じブラウザの、すべての端末に及びます。R-1 と R-4 の「ログイン状態が無効になった端末」は、そのログイン状態による、すべての端末を指します。
- この帰結は、3つあります。
  - 利用の途中で、期限に達すると、ログインし直すことになる。
  - 共用の端末でログアウトを忘れると、期限まで、ログイン状態が残る。他の端末から無効にする手段は、UC-07 を扱うスライスまでない。
  - 1つのブラウザで、同時にログインできる利用者は、1人である。動作検証は、互いに状態を共有しないブラウザで行う(WS-D6 の帰結と同じ)。

### RL-D5 上限の値と、数える単位(SEC-5)

既定値は、「上限」の表の通りです。

- 値は、既定値とし、運営者が、設定で変えられるようにします。雛形の利用者が、自らのサービスの規模に合わせて、変えるためです。ローカルの開発環境では、すべての要求が、同じ送信元になり、既定値のままでは、自動テストと動作検証が、送信元ごとの上限に当たりうるためでもあります。
- 登録の申し込みは、連絡先への送信を伴うため、他人の連絡先へ送らせる濫用を、宛先ごとの上限で抑えます。既定値は、案内が届かない場合のやり直しに足りる回数です。
- 登録の完了の上限は、1つの案内を使って、識別名が使われているかどうかを、繰り返し調べることを抑えます(AC-9)。
- ログインの、連絡先ごとの上限は、1つのアカウントへの総当たりを、既定値で、1日に960回までに抑えます。恒久的に止める案は、採りません。解く手段(UC-04、運営者による対応)が、ないためです。失敗を数える期間を限るのは、限らないと、古い失敗と合わせて拒否になり、登録されていない連絡先の計数も、増え続けるためです。送信元ごとの上限は、1つの送信元から、多くの連絡先に、少しずつ試すことを抑えます。
- 相手の特定の上限は、識別名の総当たりを抑えます(D-1)。
  - 会話を開く操作と、送信の操作も数えるのは、これらの応答からも、相手が居るかどうかが分かるためです。
  - 相手が居た要求も数え、上限の間は、居るかどうかに依らず拒否するのは、居なかった要求だけを扱うと、上限に達した後も、応答の違いから、居るかどうかが分かるためです。
  - 成立した会話がある相手を数えないのは、居ることを、既に知っている相手であるためです。会話の一覧がない間は、会話を開くたびに特定が要り、数えると、通常の利用を妨げます。
- この帰結は、6つあります。
  - 連絡先を知る人は、失敗を重ねて、本人のログインを妨げられる。拒否の間が過ぎるたびに、失敗を重ねれば、妨げ続けられる。申し込みを重ねて、本人の登録も、妨げられる。
  - 宛先ごとの上限の既定値では、申し込みを重ねる人が、1つの連絡先に、1日に72通までの案内を、届け続けられる。登録済みの連絡先にも、同じである。
  - 新しい相手との最初のやり取りは、特定、会話を開く、最初の送信で、3回と数える。既定値では、1時間に話しかけられる新しい相手は、10人までである。
  - 送信元を共有する利用者(同じ家庭、職場)は、送信元ごとの上限を、分け合う。ローカルの開発環境では、すべての要求が、同じ送信元になる。
  - 設置環境で、サーバーの前に中継を置く場合、送信元を定める方法が、別に要る。
  - 運営者が、設定で値を緩めると、総当たりと濫用の抑止は、その分、弱まる。

### RL-D6 識別名、表示名、連絡先の規則

規則は、「入力の規則」の通りです。

- 識別名は、アプリの外で教わり、手で入力するものです(D-1)。見た目の似た別の文字によって、別の利用者を特定することと、他の利用者になりすますことを避けるため、英字、数字、アンダースコアに限ります。
- 識別名は、利用者が決める名前であるため、大文字と小文字を、入力された通りに保管し、示します。重複の判定と、相手の特定での照合では、大文字と小文字を区別しません。区別すると、教わった識別名の大文字と小文字を違えて入力した人が、相手を特定できず、大文字と小文字だけが異なる識別名で、他の利用者になりすませるためです。
  - 英小文字に限る案は、採りません。利用者が、決めた通りの名前を示せないためです。
  - D-1 の「完全一致」は、大文字と小文字の違いを除いて、すべての文字が一致することと読みます。部分一致と、候補の提示は、行いません。
  - この帰結として、大文字の I と小文字の l のように、見た目の似た識別名が、英小文字に限る場合より増えます。
- 表示名は、制御文字のほか、文字の種類を制限しません(WS-D3 と同じ理由)。この帰結として、表示名は、重複でき、紛らわしくもできるため、表示名だけでは、本人を見分けられません。特定の結果には、識別名を併せて示します。
- 連絡先は、英字を小文字に揃えて扱います。大文字と小文字だけが異なる連絡先で、複数のアカウントが作られないようにするためです。この帰結として、宛先の大文字と小文字を区別するメールの仕組みを使う人は、登録できません。ASCII 以外の文字を含む連絡先も、登録できません。

### RL-D7 登録の案内

値と内容は、「登録する」の通りです。

- 有効期限は、案内が遅れて届く場合と、後から読む場合に足りる長さとします。短くすると、申し込みのやり直しが増え、宛先ごとの上限に当たります。この帰結として、確認されていない連絡先を、期限まで保管します。
- 案内を送れなかった場合は、送ったと示さず、完了できなかったことを示します。送ったと示すと、訪問者は、届かない案内を待ち続けます。案内は、連絡先が登録済みの場合にも送るため、この応答から、登録済みかどうかは分かりません。

### RL-D8 記録に、連絡先、識別名、表示名を含めない

- ログインの失敗に、入力された連絡先を記録する案は、採りません。打ち間違えた連絡先や、連絡先の欄に誤って入力された秘密が、記録に残るためです。
- 利用者は、識別名ではなく、システムが割り当てた識別子で記録します。識別名は、変更でき、他の人が再び使えるため(D-1)、後から、誰を指すのかが定まりません。
- この帰結として、登録されていない連絡先に対するログインの失敗は、送信元でしか、追えません。

### RL-D9 ログイン状態を確かめる操作は、ログインしていない場合も、拒否としない

端末は、開いた直後と、再読み込みの後に、ログイン中の利用者を知るために、ログイン状態を確かめます(RL-21)。規則は、「ログイン状態」の通りです。

- ログインしていない人がアプリを開くことは、通常の利用であり、「ログインしていない」と示すことで、操作は完了しています。拒否(操作を受け付けないこと)には、当たりません。
- 拒否とする案は、採りません。理由は3つあります。
  - ログインしていない人がアプリを開くたびに、認証の拒否が記録され、無効な資格を添えた要求と、見分けられなくなる(OPS-3)。
  - アプリを開いただけの人の送信元を、出来事として記録することになる(PRV-1)。
  - クライアントが、この操作の拒否だけを、ほかの拒否と別に扱うことになる。案内から登録を続ける訪問者には、ログインを求める画面ではなく、登録を続ける画面を示すためである。
- R-1 と AC-1 の「登録とログインを除く」の「ログイン」は、この操作を含むものと読みます。
- この帰結として、無効な資格を添えた、この操作の要求は、記録に残りません。応答から分かるのは、添えた資格が有効かどうかだけであり、資格は、推測できない無作為さを持ちます(「ログイン状態」)。

## 機能仕様

ユースケース記述が定めていない、規則、値、応答の優先順を定めます。

### 入力の規則

文字は、Unicode のコードポイントで数えます(WS-D3)。

| 項目 | 規則 |
|---|---|
| 連絡先 | 前後の空白文字を除き、英字を小文字に揃えてから、検証する。以後、その形で扱う。254文字以下。`ローカル部@ドメイン` の形で、ASCII の文字だけからなる(詳細は、表の下) |
| 識別名 | 3文字以上、20文字以下。英字(大文字、小文字)、数字、アンダースコア(`_`)だけからなる。入力された通りに保管し、示す。他の利用者の識別名と、重複しない。重複の判定では、大文字と小文字を区別しない |
| 表示名 | 前後の空白文字を除いてから、検証する。1文字以上、50文字以下。Unicode の文字列として正しい。制御文字(一般カテゴリ Cc。改行とタブを含む)を含まない |
| 秘密 | 15文字以上、128文字以下。Unicode の文字列として正しい。文字の種類は、問わない。入力された通りに扱う。よく使われる秘密の一覧にあるもの、本人の連絡先と同じもの、本人の識別名と同じものは、受け付けない。連絡先、識別名との比較では、大文字と小文字を区別しない |

- 連絡先のローカル部は、1文字以上、64文字以下で、英数字と、次の記号からなる。``. ! # $ % & ' * + / = ? ^ _ ` { | } ~ -``
- 連絡先のドメインは、`.` で区切った、2つ以上のラベルからなる。各ラベルは、1文字以上、63文字以下の、英数字とハイフンからなり、ハイフンで始まらず、ハイフンで終わらない。
- 検証は、サーバー側で行う。クライアントでの検証は、サーバー側の検証に代えない。

### 登録する(UC-01)

- 申し込みで入力するのは、連絡先だけである。
- 案内は、確認のための資格を含む。資格は、申し込みを受け付けた時点から、24時間、有効である。登録の完了によって、使用済みになる。E1、E2 の拒否では、使用済みにならない。
- 同じ連絡先で、再び申し込むと(A2)、有効期限は、新しい申し込みから数える。
- 「案内を送った」は、送信の手段に引き渡したことを指す。届いたかどうかは、システムには分からない。引き渡せなかった場合、システムは、完了できなかったことを示す。この申し込みも、上限に数える。
- 登録の完了では、ログイン状態を与えない。訪問者は、続けてログインする(UC-02)。
- 同じ識別名での登録の完了が、同時に行われた場合、完了するのは、1つだけである。同じ資格での登録の完了が、同時に行われた場合も、同じである。
- 期限を過ぎた申し込みは、連絡先とともに、期限から24時間以内に、保管データから消える(E5)。

案内の内容は、次の通りです。どちらも、訪問者が入力した内容を、宛先のほかには含めません。秘密と、他の利用者の情報を、含めません(PRV-3)。

| 場合 | 含める内容 |
|---|---|
| 連絡先が登録されていない(基本フロー、A2) | 登録を続ける手段(確認のための資格を含む)、有効期限、心当たりがない場合は、何もしなくてよいこと |
| 連絡先が登録済みである(A1) | 登録の申し込みがあったこと、登録済みであること、心当たりがない場合は、何もしなくてよいこと。資格は、含めない |

システムは、次の場合に拒否します。複数の場合に当たる要求には、表の上にあるものの応答を返します。

| 操作 | 場合 | 応答 | フロー |
|---|---|---|---|
| 申し込み | 連絡先が、入力の規則を満たさない | 正しくないことを示す | E1 |
| 申し込み | 上限を超えた | 上限を超えたことを示す | E4 |
| 完了 | 上限を超えた | 上限を超えたことを示す | E4 |
| 完了 | 確認のための資格が、無効である | 無効である理由を区別せずに、申し込み直しを求める | E3 |
| 完了 | 識別名、表示名、秘密が、入力の規則を満たさない | 正しくない項目を、すべて示す | E1 |
| 完了 | 識別名が使われている | 別の識別名を求める | E2 |

資格の確認を、識別名の確認より先に行うのは、識別名が使われているかどうかを、案内を受け取った人にだけ示すためです(UC-01 基本フローの注記)。

### ログインする(UC-02)

- 訪問者は、連絡先と秘密を入力する(RL-D2)。
- システムは、ログインのたびに、新しいログイン状態を与える。ログイン状態を持つブラウザで、ログインした場合、それまでのログイン状態は、無効にする。
- 入力の規則を満たさない連絡先と秘密は、照合の失敗として扱い、同じ応答を返す(E1)。
- 上限に達している間は、照合を行わずに拒否する(E2)。

### ログイン状態(R-1)

- ログイン状態は、ログインから30日で、無効になる。操作によって、延びない。
- ログイン状態は、ブラウザが保ち、同じブラウザのタブが共有する。再読み込みの後も、ブラウザを閉じて開き直した後も、サーバーを再起動した後も、有効期限まで保たれる。登録の申し込みも、サーバーを再起動した後に保たれる。
- ログイン状態を示す資格と、確認のための資格は、128ビット以上の無作為さを持つ(OWASP ASVS 5.0.0 7.2.3。2026-11-26 に確かめた)。
- システムは、登録とログインを除く、すべての操作と、リアルタイムの接続を、ログイン状態が有効な場合に限って受け付ける。この確認は、ほかの検証と認可より先に行う。拒否の応答は、資格がない、正しくない、有効期限が切れた、ログアウトした、のどれであるかを区別しない。
- ログイン状態を確かめる操作(端末が、ログイン中の利用者を知るための操作)は、上の拒否の対象としない。ログイン状態が有効な場合は、ログイン中の利用者を示す。有効でない場合は、上の4つのどれであるかを区別せずに、ログインしていないことを示し、認証の拒否として記録しない(RL-D9)。
- ログイン状態の確認を完了できなかった場合(保管先に届かないなど)、システムは、操作を受け付けない。
- ログイン状態が無効になった時点から、そのログイン状態による端末には、配信を届けない(R-4)。
- 拒否を受けたクライアントは、ログインを求める画面を示す。それまでに示していた、会話の内容と、利用者の情報を、示し続けない。入力中の本文は、保たない。次にログインする人が、別の利用者でありうるためである。
- リアルタイムの接続を保っている端末は、ログイン状態が無効になると、操作なしに、同じく、ログインを求める画面を示す。接続が切れている端末は、次の操作で拒否を受けたときに示す。
- 同じブラウザの別のタブで、別の利用者としてログインし直された端末は、前の利用者の会話を示し続けない。前の利用者を示したまま、新しい利用者として操作を行わない。

### ログアウトする(UC-03)

- ログアウトは、そのログイン状態を無効にする。同じブラウザの、すべてのタブに及ぶ。他のブラウザのログイン状態は、残る。
- ログアウトを完了できなかった場合(要求が届かないなど)、クライアントは、できなかったことを示す。ログアウトしたものとして、示さない。ログイン状態が、有効なまま残っているためである。

### 相手を特定する(UC-08)

- 特定の対象は、登録を完了した利用者である。
- 識別名の照合では、大文字と小文字を区別しない(自分自身を指定したかどうかの判定を含む)。
- 特定の結果として示すのは、相手の識別名と表示名である。識別名は、相手が登録した通りに示す。
- 利用者は、特定した相手との会話を開く。以後は、ウォーキングスケルトンの仕様「会話を開く」「メッセージを送る」の通りである。同仕様の拒否の表の「相手が固定ユーザーの中に居ない」は、「相手が、登録を完了した利用者の中に居ない」に読み替える。

システムは、次の場合に、特定を拒否します。複数の場合に当たる要求には、表の上にあるものの応答を返します。

| 場合 | 応答 | フロー |
|---|---|---|
| 入力が、識別名の規則を満たさない | 正しくないことを示す | R-3 |
| 自分自身を指定した | 相手にできないことを示す | E2 |
| 上限を超えた | 上限を超えたことを示す | E3 |
| 一致する利用者が居ない | 見つからないことを示す。候補は、示さない | E1 |

### 上限(SEC-5)

「T に N 回」は、直近の T の間に数えた回数が、N に達している間、次の要求を拒否することを指します。上限によって拒否した要求は、数えません。

表の値は、既定値です。運営者は、回数と時間を、設定で変えられます。設定がない値は、既定値で働きます。正の値でない設定では、サーバーは、起動しません。

| 操作 | 数える単位 | 上限(既定値) | 数えるもの | フロー |
|---|---|---|---|---|
| 登録の申し込み | 送信元 | 1時間に10回 | 連絡先が正しい申し込み(A1、A2 を含む) | UC-01 E4 |
| 登録の申し込み | 宛先の連絡先 | 1時間に3回 | 同上 | UC-01 E4 |
| 登録の完了 | 送信元 | 1時間に20回 | 完了の要求(E1〜E3 で拒否されたものを含む) | UC-01 E4 |
| ログイン | 連絡先 | 直近15分の失敗が、連続して10回に達すると、最後の失敗から15分間、拒否する | 照合の失敗。成功すると、0に戻る | UC-02 E2 |
| ログイン | 送信元 | 15分に30回 | 照合の失敗 | UC-02 E2 |
| 相手の特定 | 利用者 | 1時間に30回 | 成立した会話がない相手を指定した要求(表の下) | UC-08 E3 |

- ログインの、連絡先ごとの上限は、登録されていない連絡先にも、同じく働く。拒否の間は、秘密が正しくても拒否し、失敗に数えない。拒否の間が過ぎると、0から数える。既に与えたログイン状態には、影響しない。入力の規則を満たさない連絡先でのログインは、連絡先ごとには数えず、送信元ごとにだけ数える。
- 宛先の連絡先ごとの上限は、連絡先が登録済みかどうかに依らず、同じく働く。
- 相手の特定の上限は、次の通りに働く。
  - 数えるのは、特定の操作、会話を開く要求、送信する要求のうち、自分との間に成立した会話がない相手を指定したものである。一致する利用者が居たかどうかに、依らない。
  - 入力の規則を満たさない要求と、自分自身を指定した要求は、数えない。
  - 上限に達している間は、数える対象の要求を、一致する利用者が居るかどうかに依らず、同じ応答で拒否する。
  - 成立した会話がある相手を指定した要求は、数えず、上限に達している間も、受け付ける。
  - 会話を開く操作と、送信の操作では、「上限を超えた」を、ウォーキングスケルトンの仕様の拒否の表の、「相手として自分自身を指定した」の次に置く。
- 計数は、サーバーの再起動で失われてよい。再起動を行えるのは、運営者だけであるためです。

### 記録(R-6)

| 出来事 | 記録する場合 |
|---|---|
| 登録の申し込み | 受け付けた。案内を送れなかった場合は、その旨 |
| 登録の完了 | 完了した |
| ログインの成功、失敗 | 照合に成功した、失敗した |
| ログアウト | 完了した |
| 認証の拒否 | ログイン状態が有効でない要求を、拒否した |
| 上限の超過 | 上限によって、拒否した。数える単位の種類を、併せて記録する |
| エラー | 操作を完了できなかった |

- 記録する項目は、発生時刻、出来事の種類、利用者の識別子(特定できた場合)、送信元である。
- 秘密、ログイン状態を示す資格、確認のための資格、連絡先、識別名、表示名、メッセージの本文は、記録しない。
