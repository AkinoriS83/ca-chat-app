### OBS-002

| 項目 | 内容 |
|---|---|
| 日付 | 2026-11-20 |
| スライスと工程 | ウォーキングスケルトン、設計(ADRのレビュー) |
| 区分 | 妨げ |
| 出来事 | WebSocket を、1つの adapter のパッケージで扱う構成にしていた。このパッケージは、ユースケースを呼び、かつ、配信のポートを実装するため、usecase、port、domain のすべての import を許す、規則の例外になっていた。レビューで、リアルタイムの経路でだけ、飛ばしを検出できないことに気付いた。パッケージを、接続の受け付けと、配信の2つに分け、接続を、ユースケースを経由して渡す形に改めた |
| 関わる構造 | adapter の層。依存規則と飛ばし禁止。境界要素(接続への書き込み口のインターフェイス、接続を登録するポート、登録を解くポート) |
| 手がかり | [ADR-005](adr/ADR-005-layer-structure.md)「WebSocket を扱う adapter の分割」 |
| 所見 | 外部の相手が双方向である場合、「ユースケースを呼ぶ adapter」と「ポートを実装する adapter」の二分に、そのままでは収まらなかった。規則を保つために、境界要素が3つと、ポートを呼ぶだけのユースケースが増えた。一方で、配信の adapter は、WebSocket のライブラリに依存しなくなった。実装の前であり、増えた要素が妨げになるかどうかは、まだ分からない。構造がなかった場合との差は、推測である |
