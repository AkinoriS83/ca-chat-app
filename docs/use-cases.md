# ユースケース記述

本書は、[開発方針](development-policy.md)が定める開発の流れのうち、ユースケースフェーズの成果物です。プロジェクト全体(フェーズ1〜4)を対象に、[企画書](project-plan.md)の機能スコープを、利用者の目的ごとのユースケースとして記述します。

本書の前提は次の通りです。

- 企画書が「ユースケースで定める」とした事項は、本書で判断し、理由とともに記載する(「本書で判断した事項」)。
- 特定の技術要素、画面の構成、操作の手段は記述しない。認証の方式、連絡先の確認と再設定の手順、上限値と有効期限は、仕様で定める(企画書「仕様以降で決める事項」)。
- 背景と用語は、開発方針、[仮説](hypothesis.md)、企画書に従う。本書で新たに使う用語は「用語」に定める。
- 仕様フェーズでは、各機能スライスの受け入れ基準から、本書のユースケースとフローをIDで参照する(企画書「各マイルストーンに共通の完了条件」1)。IDは、本書を改訂しても振り直さず、欠番を許す。

## 記述の形式

各ユースケースは、次の項目で記述します。

| 項目 | 内容 |
|---|---|
| フェーズ | そのユースケースを実装するフェーズ。会話の種類によって異なる場合は併記する |
| アクター | そのユースケースで目的を達成する人 |
| 事前条件 | 開始時に成り立っていること。ログイン済みであること(R-1)は、訪問者のユースケースを除くすべてに共通するため、個別には書かない |
| 基本フロー | 目的を達成する標準の流れ。手順に番号を付ける |
| 代替フロー(A) | 基本フローと異なる経路で、目的を達成する流れ |
| 例外フロー(E) | 目的を達成できずに終わる流れ |
| 事後条件 | 終了時に成り立っていること |
| 関連する水準 | 企画書の非機能要件の目標水準のうち、そのユースケースに関わるもの。仕様で受け入れ基準に落とすときの手がかりであり、網羅を保証するものではない |

フローは「UC-09 基本フロー」「UC-09 A1」「UC-09 E4」の形で参照します。フェーズを括弧で付したフロー(例:「E4(フェーズ2)」)は、そのフェーズから適用します。

## アクター

| アクター | 説明 |
|---|---|
| 訪問者 | 登録していない人、またはログインしていない人 |
| 利用者 | 登録を済ませ、ログインしている人。ユースケースの中では、送信者、管理者などの役割で呼ぶ |

運営者と雛形の利用者は、アプリの機能を使う立場としては登場しません。運営者向けの管理機能は対象外であり(企画書「開発方針に挙がっていない機能の採否」)、設置・更新・バックアップ・復元は手順書に従って行うためです(OPS-1、OPS-5)。企画書の利用シナリオ11(雛形の利用者による構築と公開)は、「雛形としての公開条件」の文書で扱い、本書の対象としません。

## 用語

| 用語 | 意味 |
|---|---|
| 連絡先 | 登録時に本人が受け取れることを確認するメールアドレス。本人以外には見せない |
| 識別名 | 利用者が自分で決める、設置環境の中で重複しない名前。相手を特定するために使う |
| 表示名 | 会話の中で、利用者の名前として表示するもの。他の利用者と重複してよい |
| プロフィール | 他の利用者に見せる利用者の情報。識別名と表示名からなる |
| 会話 | メッセージをやり取りする場。1on1会話とグループ会話がある |
| 1on1会話 | 2人の利用者の間の会話。同じ2人の間に1つだけ存在する |
| グループ会話(グループ) | 名前を持ち、複数の利用者が参加する会話 |
| 参加者 | ある会話に参加している利用者。グループの参加者は、管理者1人とメンバーからなる |
| 会話を共有する | 2人の利用者が、同じ会話の参加者であること |
| オンライン | 利用者がログインし、1つ以上の端末でアプリを開いている状態。そうでない状態をオフラインという |
| 既読の位置 | ある利用者が、ある会話のどのメッセージまで読んだかを示す位置。本人以外に見せるのは、1on1会話の相手に限る(D-11) |
| 未読 | 既読の位置より後にある、他の参加者のメッセージ |
| 通話 | 会話の中で行う、音声(フェーズ4以降は映像と画面を含む)によるやり取り。1つの会話で同時に行える通話は1つとする |
| 参加者の変化の記録 | グループの参加者の変化(追加、除外、退出、管理者の変更)を、会話の中に残す記録。メッセージではない(D-12) |
| 削除済みユーザーの表示 | 退会した利用者を示す、本人を識別できない表示。具体的な表示はフェーズ2の設計で定める |

## 本書で判断した事項

企画書が「ユースケースで定める」とした事項(D-1、D-2、D-4〜D-6、D-10)と、ユースケースを記述する上で定める必要があった事項(D-3、D-7、D-9、D-11、D-12)です。D-8は欠番です(ブロックに関する判断であり、企画書がブロックを対象外としたため)。

### D-1 相手を特定する手段(AC-7)

相手の識別名を、完全一致で指定して特定します。部分一致による検索や、候補の提示は提供しません。会話を共有する相手は、識別名を入力せずに、会話の中から選べます(例: グループの他の参加者と1on1会話を始める)。

- 完全一致に限るのは、全利用者を列挙できる一覧を提供しない(AC-7)ためです。部分一致を許すと、短い語句を繰り返すことで列挙できます。完全一致でも総当たりは可能なため、特定の操作に頻度の上限を設けます(SEC-5)。
- 連絡先で特定する手段は採りません。ある連絡先が登録済みかどうかが分かり(AC-9)、連絡先を他の利用者に見せない(PRV-2)ことにも反するためです。
- 識別名は、アプリの外で相手から教わることを前提とします。
- 識別名は、本人が変更できます(UC-05)。望まない相手に識別名を知られた利用者が、自分でその識別名を無効にできるようにするためです。運営者が利用を停止する機能も、相手を遮断する機能(ブロック)も持たないため、新たに特定されることを防ぐ手段は、これに限られます(D-10)。
- 変更または退会によって使われなくなった識別名は、他の人が登録や変更に使えます(UC-05、UC-28)。使われなくなった識別名を、誰のものであったかとともに保管し続けないためです(PRV-1、PRV-6)。この帰結として、以前の識別名を教わっていた人がその識別名を指定すると、後からその識別名を使い始めた別の利用者を特定することがあります。

### D-2 利用者の情報を見せる相手の範囲(AC-7)

| 情報 | 見せる相手 |
|---|---|
| プロフィール(識別名、表示名) | その利用者の識別名を完全一致で指定した利用者。会話を共有する利用者 |
| プレゼンス | 会話を共有する利用者 |
| 連絡先 | 本人のみ |

- プレゼンスは、識別名を指定しただけの相手には見せません。会話を始めるのに必要なのは相手を特定できることであり、プレゼンスはその後のやり取りのための情報です。
- この帰結として、ある利用者に1on1でメッセージを送る(D-3)か、グループに追加する(D-4)と、その相手のプレゼンスが見えるようになります。見られる側が、これを相手ごとに防ぐ手段は持ちません(D-10)。
- メッセージの送信者、リアクションを付けた利用者、参加者の変化の記録(D-12)に現れる利用者としての表示名は、その利用者がグループから退出・除外された後も、その会話の参加者に見せます。

### D-3 1on1会話の成立

1on1会話は、どちらかが最初のメッセージを送信した時点で成立し、双方の会話の一覧に現れます。相手の承諾は要しません。

- 相手を特定しただけでは、会話は成立しません。メッセージのない会話が相手の一覧に現れることと、送信を伴わずに相手のプレゼンスが見えることを避けるためです。
- 承諾の手順を設けないのは、対象ユーザーが数十人程度のコミュニティの一員であり、識別名をアプリの外で相手から教わる関係(D-1)を前提とするためです。望まない相手からのメッセージを止める手段は持ちません(D-10)。

### D-4 グループ内の権限(AC-4)

グループの参加者の役割は、管理者とメンバーの2つとします。管理者は常に1人で、グループを作成した利用者が最初の管理者になります。

| 操作 | 管理者 | メンバー |
|---|---|---|
| 会話の利用(メッセージの閲覧・送信、リアクション、検索、通話、ファイルの共有) | できる | できる |
| 自分のメッセージの編集・削除 | できる | できる |
| グループからの退出 | できる | できる |
| メンバーの追加・除外 | できる | できない |
| グループ名の変更 | できる | できない |
| 管理者の譲渡 | できる | できない |

- 規則を「グループを変える操作は管理者、会話の利用は参加者全員」の1つに絞り、認可の判定とその確認を単純に保ちます。
- 管理者も、他の参加者のメッセージを編集・削除できません(AC-3)。
- 追加に、追加される側の承諾は要しません。追加された利用者は退出できます(UC-17)。退出した後に、再び追加されることを止める手段は持ちません(D-10)。
- グループを削除する操作は設けません。グループは、最後の参加者が居なくなった時点で消えます(UC-17 A2)。

### D-5 グループの人数の上限

1つのグループの参加者は、100人までとします。想定規模(利用者数十人程度)の全員が1つのグループに参加できる値であり、リアルタイム配信の宛先の数に上限を与えるためです。

### D-6 管理者が居なくなるグループの扱い

管理者が退出または退会するとき、他に参加者が居れば、参加した時期が最も古い参加者が管理者になります。管理者は、退出の前に、任意のメンバーへ管理者を譲渡することもできます(UC-19)。最後の参加者が退出または退会したグループは、メッセージとともに保管データから削除します。

- 退出と退会で同じ規則を使い、管理者の居ないグループが生じないようにします。
- 参加者の居ないグループのメッセージは、誰も読めないため、保管し続けません(PRV-1)。

### D-7 グループの履歴を読める範囲

グループの参加者は、自分が参加する前のメッセージを含め、その会話のすべての履歴を読めます。退出・除外された利用者は、その時点から、その会話を読むことも書くこともできません。

- 認可を「その会話の参加者かどうか」だけで判定できるようにするためです(AC-2)。参加した時点で区切ると、メッセージごとに読める人が変わり、検索、既読、リアクションのすべてに条件が加わります。
- この帰結は2つあります。
  - メンバーを追加すると、それまでの発言が、追加された利用者に見えるようになります。追加は会話に記録するため(D-12)、参加者は、追加があったことを会話の中で知ることができます。
  - グループから退出・除外された利用者は、そのグループに残した自分のメッセージを編集・削除できなくなり、自分が付けたリアクションも取り消せなくなります。メッセージとリアクションは、グループに残ります。メッセージを消す手段は、退出の前に削除することと、退会時に削除を選ぶこと(UC-28)です。除外の場合は、事前に削除する機会がないため、後者に限られます。

### D-9 相手が退会した1on1会話の扱い

相手が退会した1on1会話は、残った利用者の会話の一覧に残ります。残った利用者は、履歴を読むことと、自分のメッセージを削除することができます。メッセージの送信・編集、リアクション、通話の開始はできません。退会した相手のメッセージは、相手が退会時に選んだ通りに、削除されているか、送信者を削除済みユーザーの表示に置き換えて残ります(PRV-6)。

残った利用者も退会した場合、その1on1会話は、メッセージとともに保管データから削除します。

- 誰も読めない会話を、保管し続けないためです(D-6と同じ。PRV-1)。
- 後から退会する利用者が、メッセージを残すことを選んでいても、削除します。
- 退会時の選択肢(UC-28 手順3)は、会話の状態によって変えません。対象となる会話は複数ありえ、それぞれの状態に応じて選択肢を変えると、分かりにくくなるためです。

### D-10 望まない相手への対処

企画書は、ブロック(望まない相手を利用者自身が遮断する機能)を、雛形の到達(フェーズ3の完了)までの対象外としています。到達後に追加するかどうかと、その時期は、フェーズ3の完了時に判断します(企画書「ブロックを対象外とする判断」)。本書のユースケースは、ブロックを前提とせずに定めます。望まない相手に対して、利用者が自分でできることは、次に限られます。

| 状況 | できること | できないこと |
|---|---|---|
| 識別名を知られた | 識別名を変更する(UC-05)。以後、以前の識別名では特定されない | 既に成立した1on1会話と、共に参加するグループを通じたやり取りを、識別名の変更で断つこと |
| 1on1会話でメッセージが届く | なし | その相手からの送信を止めること。その相手に、自分のプレゼンスを見せないこと |
| 1on1会話またはグループで、通話を始められる(フェーズ3) | 知らせに応じない(UC-30 A1)。グループであれば、退出する(UC-17) | 通話の開始の知らせが届くのを止めること |
| グループに追加された | 退出する(UC-17)。そのグループだけを共有していた相手には、以後、プレゼンスが見えない | 再び追加されることを止めること |

- 1on1会話の成立(D-3)とグループへの追加(D-4)に承諾を要しない判断は、ブロックがないことを理由に変えません。対象ユーザーは数十人程度のコミュニティの一員であり、識別名をアプリの外で相手から教わる関係を前提とするためです。
- 頻度の上限(SEC-5)は、送信、追加、通話の開始の量を抑えますが、特定の相手からの操作を止めるものではありません。
- 上記の「できないこと」は、雛形の限界として、雛形の文書に明記します(企画書「雛形としての公開条件」)。
- ブロックを追加する場合は、本書を改訂します。その際、ブロックの要件は、企画書が定める範囲で定めます。すなわち、ブロックの関係(一方が他方をブロックしている)にない利用者の間では、既存のフローの振る舞いを変えず、ブロックの関係にある利用者の間に限り、既存のフローに条件を追加します。

### D-11 既読を見せる相手の範囲

既読の位置を本人以外に見せるのは、1on1会話の相手に限ります。グループでは、既読の位置は本人にのみ見え、本人の未読(UC-20)を定めるためにだけ使います。

- グループの参加者は、自分が参加する前のメッセージを読めます(D-7)。この前提でメッセージごとに「誰が読んだか」を示すと、後から追加された利用者が、過去のすべてのメッセージをまだ読んでいない参加者として現れるなど、表示の意味が定まりません。
- 調査した範囲では、参加する前の履歴を読めるポピュラーなチャットサービスは、グループで他の参加者の既読を示していません。
- グループに追加された利用者の既読の位置は、追加された時点から始めます。それより前のメッセージは、読めますが、未読として扱いません(UC-15)。
- この帰結として、自分のメッセージがどこまで読まれたかを確かめられるのは、1on1会話に限られます(企画書の利用シナリオ6、PRV-2)。グループでは、確かめる手段を持ちません。

### D-12 グループの参加者の変化の記録

グループの参加者の変化は、その会話の中に、メッセージと同じ時系列で記録します。記録する変化は、次の通りです。

| 変化 | 記録する場合 |
|---|---|
| 追加 | メンバーを追加した(UC-15) |
| 除外 | メンバーを除外した(UC-16) |
| 退出 | 参加者が退出した(UC-17)。退会によってグループから外れた場合(UC-28)を含む |
| 管理者の変更 | 管理者を譲渡した(UC-19)。管理者の退出・退会によって交代した場合(D-6)を含む |

- 記録するのは、参加者の変化が、会話を読める人と、グループを変えられる人を変えるためです。特に、追加は、それまでの発言を読める人を増やします(D-7)。変化の時点で不在だった参加者も、会話を読めば、変化に気付けます。
- 記録には、変化の種類、対象の利用者、日時を示します。操作した管理者を示すかどうかは、フェーズ2の仕様で定めます。
- グループ名の変更は、記録しません。読める人も、変えられる人も変わらないためです。グループの作成時に指定した参加者も、記録しません。それより前のメッセージがないためです。
- 記録は、メッセージではありません。編集・削除、リアクション、検索の対象とせず、未読を生じさせません。
- 記録は、その会話の参加者が、履歴の一部として読めます(D-7)。グループが消えるとき、ともに削除します(D-6)。
- 記録に現れる利用者が退会した場合、その利用者を、削除済みユーザーの表示に置き換えます(PRV-6)。退会時にメッセージを削除するか残すかの選択には、依りません。

## 共通の規則

すべてのユースケースに共通する規則です。各ユースケースでは繰り返しません。

- **R-1 ログイン済みであること**: 訪問者のユースケース(UC-01、UC-02、UC-04)を除くすべてのユースケースは、ログイン済みであることを事前条件とする。ログイン状態が無効な場合(有効期限が切れた、ログアウトした、認証に用いる秘密の変更・再設定によって無効にされた、退会した)、システムは操作を拒否し、ログインを求める(AC-1、SEC-3)。ログイン状態が無効になった端末は、その時点から、アプリを開いている端末として扱わない。すなわち、リアルタイムの配信を届けず(R-4)、オンラインの判定に数えず(UC-12)、その端末で参加している通話から外す(UC-31 A4、フェーズ3)。
- **R-2 存在の秘匿**: 認可されない資源(参加していない会話とそのメッセージ、見せる範囲にない利用者など)への操作は、その資源が存在しない場合と同じ応答で拒否する。各ユースケースの「見つからない」は、存在しない場合と認可されない場合の両方を指す(AC-5)。
- **R-3 入力の検証と上限**: システムは、入力をサーバー側で検証する。形式が正しくない入力と、長さ・大きさ・頻度の上限を超えた要求は拒否し、拒否したことを利用者に示す。上限の値は仕様で定める(SEC-4、SEC-5)。
- **R-4 リアルタイム配信の宛先**: リアルタイムに届ける情報は、届ける時点で、その情報を見ることを認可されている利用者にのみ届ける。参加関係を失った利用者と、ログイン状態が無効になった端末(R-1)には、その時点から届けない(AC-6、SEC-3)。
- **R-5 分割しての取得**: 一覧、履歴、検索結果は、分割して取得する。1回に取得する件数は仕様で定める(PERF-2)。
- **R-6 記録**: システムは、エラー、認証の成功・失敗、認可の拒否、上限の超過を、発生時刻とともに記録する。メッセージの本文、ファイルの内容、認証に関わる秘密と資格は記録しない(OPS-3、PRV-4、SEC-1)。

## フェーズ1(MVP)

### UC-01 登録する

- **フェーズ**: 1
- **アクター**: 訪問者
- **事前条件**: なし

**基本フロー**

1. 訪問者は、連絡先を入力して、登録を申し込む。
2. システムは、入力を検証し、連絡先へ確認のための案内を送る。
3. システムは、案内を送ったことを訪問者に示す。
4. 訪問者は、連絡先に届いた案内に従って、識別名、表示名、認証に用いる秘密を入力する。
5. システムは、入力を検証し、連絡先を確認済みとして登録を完了する。訪問者は、ログインできる状態になる。

識別名、表示名、認証に用いる秘密を、連絡先の確認の後に入力するのは、次のためです。確認の手順は、仕様で定めます。

- 連絡先を受け取れない人が決めた秘密で、ログインできるアカウントが作られない。
- 識別名の重複(E2)を示す相手が、その連絡先を受け取れる人に限られる。応答から、連絡先が登録済みかどうかを区別できない(AC-9)。
- 登録を完了しない申し込みが、識別名を確保しない。

**代替フロー**

- **A1 連絡先が登録済みである**: システムは、手順2〜3と内容から区別できない応答を返す。新しいアカウントは作らない。その連絡先へは、登録済みであることを伝える案内を送る。
- **A2 同じ連絡先で、再び申し込む**(案内の再送、最初からのやり直し): 訪問者は、登録を完了する前に、同じ連絡先で再び申し込める。システムは、以前の案内を使えなくした上で、新しい案内を送る。後の申し込みだけが有効である。

**例外フロー**

- **E1 入力が正しくない**: システムは、正しくない項目を示して拒否する(R-3)。手順4の入力である場合、訪問者は、同じ案内のまま入力し直せる。
- **E2 識別名が使われている**: システムは、別の識別名を求める。訪問者は、同じ案内のまま入力し直せる。
- **E3 確認のための資格が無効である**(有効期限が切れた、使用済みである、正しくない、後の申し込みによって使えなくなった): システムは、登録を完了しない。訪問者は、登録を申し込み直す。
- **E4 上限を超えた**(送信元ごと、宛先の連絡先ごと): システムは拒否する(R-3)。
- **E5 登録を完了しないまま、有効期限を過ぎた**: システムは、申し込みを、その連絡先とともに破棄する。

**事後条件**

- アカウントが作られ、連絡先は確認済みである。
- 登録を完了するまでは、アカウントは作られない。ログインできず、他の利用者から特定されず、識別名も確保されない。
- 識別名、表示名、認証に用いる秘密を決められるのは、連絡先に届いた案内を受け取った人に限られる。

**関連する水準**: SEC-1、SEC-3、SEC-5、AC-9、PRV-1、PRV-3

### UC-02 ログインする

- **フェーズ**: 1
- **アクター**: 訪問者
- **事前条件**: 登録を完了している

**基本フロー**

1. 訪問者は、認証に必要な情報を入力する。
2. システムは、情報を照合し、有効期限のあるログイン状態を与える。
3. 利用者は、アプリの機能を使えるようになり、オンラインになる(UC-12)。

**代替フロー**

- **A1 他の端末でログインしている**: システムは、新しいログイン状態を与える。他の端末のログイン状態は有効なまま残る。

**例外フロー**

- **E1 照合に失敗した**: システムは、理由(アカウントがない、秘密が違う)を区別せずに拒否する。登録を完了していない申し込み(UC-01)は、アカウントがない場合に当たる。
- **E2 連続した失敗が上限に達した**: システムは、以後の試行を一定の間、拒否する。この応答は、アカウントの有無によって変わらない。

**事後条件**

- 利用者は、有効期限のあるログイン状態を持つ。

**関連する水準**: SEC-1、SEC-3、SEC-5、AC-9、OPS-3

### UC-03 ログアウトする

- **フェーズ**: 1
- **アクター**: 利用者

**基本フロー**

1. 利用者は、ログアウトを求める。
2. システムは、その端末のログイン状態を無効にする。
3. 利用者が他の端末でアプリを開いていなければ、利用者はオフラインになる(UC-12)。

**代替フロー**

- **A1 その端末で通話に参加している(フェーズ3)**: システムは、利用者を通話から外す(UC-31 A4)。

**事後条件**

- そのログインで得た資格では、操作できない。
- 他の端末のログイン状態は、有効なまま残る。

**関連する水準**: SEC-3

### UC-04 認証に用いる秘密を再設定する

- **フェーズ**: 1
- **アクター**: 訪問者
- **事前条件**: 登録を完了している

**基本フロー**

1. 訪問者は、連絡先を入力して、再設定を申し込む。
2. システムは、その連絡先へ再設定のための案内を送り、送ったことを訪問者に示す。
3. 訪問者は、連絡先に届いた案内に従って、新しい秘密を入力する。
4. システムは、認証に用いる秘密を置き換え、その利用者のすべてのログイン状態を無効にする。
5. 訪問者は、新しい秘密でログインする(UC-02)。

**代替フロー**

- **A1 連絡先が登録されていない**(登録を完了していない申し込みを含む): システムは、手順2と内容から区別できない応答を返す。案内は送らない。
- **A2 再設定を完了する前に、再び申し込む**: システムは、以前の案内を使えなくした上で、新しい案内を送る。後の申し込みだけが有効である。

**例外フロー**

- **E1 再設定のための資格が無効である**(有効期限が切れた、使用済みである、正しくない): システムは、秘密を置き換えない。訪問者は、再設定を申し込み直す。
- **E2 新しい秘密が条件を満たさない**: システムは、条件を示して拒否する。
- **E3 上限を超えた**(送信元ごと、宛先の連絡先ごと): システムは拒否する(R-3)。

**事後条件**

- 以前の秘密では、ログインできない。
- 再設定の前に与えたログイン状態は、すべて無効である。

**関連する水準**: SEC-1、SEC-3、SEC-5、AC-9、PRV-3

### UC-05 プロフィールを編集する

- **フェーズ**: 1
- **アクター**: 利用者

**基本フロー**

1. 利用者は、自分の表示名または識別名を書き換える。
2. システムは、入力を検証して保存する。
3. システムは、変更後のプロフィールを、見せる範囲(D-2)の利用者に反映する。

**例外フロー**

- **E1 入力が正しくない**: システムは、正しくない項目を示して拒否する(R-3)。
- **E2 識別名が使われている**: システムは、別の識別名を求める。
- **E3 上限を超えた**: システムは拒否する(R-3)。

**事後条件**

- 識別名を変更した場合、以前の識別名ではその利用者を特定できない。以前の識別名は、他の人が登録や変更に使える。
- 過去に送信したメッセージの送信者の表示も、変更後の表示名になる。

**関連する水準**: AC-3、AC-7、SEC-5

### UC-06 連絡先を変更する

- **フェーズ**: 1
- **アクター**: 利用者

**基本フロー**

1. 利用者は、連絡先の変更を求める。
2. システムは、利用者が本人であることを確かめ直す(手段は仕様で定める)。
3. 利用者は、新しい連絡先を入力する。
4. システムは、新しい連絡先へ確認のための案内を送り、送ったことを利用者に示す。
5. 利用者は、新しい連絡先に届いた案内に従って、確認を完了する。
6. システムは、連絡先を置き換える。

**代替フロー**

- **A1 新しい連絡先が、他の利用者の連絡先として登録済みである**: システムは、手順4と内容から区別できない応答を返す。連絡先は置き換えない。
- **A2 確認を完了する前に、再び変更を求める**: システムは、以前の案内を使えなくした上で、新しい案内を送る。後に求めた変更だけが有効である。

**例外フロー**

- **E1 本人であることを確かめられない**: システムは拒否する。連続した失敗は、UC-02 E2と同じく制限する。
- **E2 確認のための資格が無効である**(有効期限が切れた、使用済みである、正しくない、後に求めた変更によって使えなくなった): システムは、連絡先を置き換えない。
- **E3 上限を超えた**(利用者ごと、宛先の連絡先ごと): システムは拒否する(R-3)。

**事後条件**

- 確認を完了するまでは、以前の連絡先が有効である。
- 置き換えた後は、以前の連絡先では再設定(UC-04)できない。置き換えの前に、以前の連絡先へ送った再設定の案内も、使えなくなる。

**関連する水準**: AC-3、AC-9、SEC-3、SEC-5、PRV-3

### UC-07 認証に用いる秘密を変更する

- **フェーズ**: 1
- **アクター**: 利用者

**基本フロー**

1. 利用者は、現在の秘密と新しい秘密を入力する。
2. システムは、現在の秘密を照合し、新しい秘密に置き換える。
3. システムは、操作した端末を除く、その利用者のすべてのログイン状態を無効にする。

**例外フロー**

- **E1 現在の秘密が違う**: システムは拒否する。連続した失敗は、UC-02 E2と同じく制限する。
- **E2 新しい秘密が条件を満たさない**: システムは、条件を示して拒否する。

**事後条件**

- 以前の秘密では、ログインできない。
- 操作した端末のログイン状態は、有効なまま残る。

**関連する水準**: SEC-1、SEC-3、SEC-5、AC-3

### UC-08 相手を特定する

- **フェーズ**: 1
- **アクター**: 利用者

**基本フロー**

1. 利用者は、相手の識別名を入力する。
2. システムは、識別名が完全に一致する利用者のプロフィールを示す。
3. 利用者は、その相手との1on1会話を開く。会話は、最初のメッセージを送信した時点で成立する(UC-09 A1)。

**代替フロー**

- **A1 その相手との1on1会話が既にある**: システムは、その会話を開く。
- **A2 会話を共有する相手を選ぶ(フェーズ2)**: 利用者は、識別名を入力せずに、グループの他の参加者など会話を共有する相手を、会話の中から選ぶ。

特定した相手は、グループへの追加(UC-14、UC-15)の対象としても使います(フェーズ2)。

**例外フロー**

- **E1 見つからない**: 一致する利用者が居ない場合、システムは、見つからないことを示す。
- **E2 自分自身を指定した**: システムは、相手にできないことを示す。
- **E3 上限を超えた**: システムは拒否する(R-3)。

**事後条件**

- 特定しただけでは、相手には何も知らされず、相手のプレゼンスも見えない(D-2、D-3)。

**関連する水準**: AC-5、AC-7、SEC-5

### UC-09 メッセージを送る

- **フェーズ**: 1(1on1会話)、2(グループ会話)
- **アクター**: 利用者(送信者)
- **事前条件**: 送信者が、その会話の参加者である。または、1on1会話の相手を特定している(UC-08)

**基本フロー**

1. 送信者は、会話の中で本文を入力し、送信する。
2. システムは、本文を検証して保管し、送信が完了したことを送信者に示す。
3. システムは、オンラインである他の参加者に、メッセージを即時に届ける。送信者が他の端末でアプリを開いている場合は、その端末にも届ける。
4. オフラインの参加者は、次にアプリを開いたときに、メッセージを読める(UC-11)。

**代替フロー**

- **A1 1on1会話の最初のメッセージである**: システムは、1on1会話を成立させる。会話は、双方の会話の一覧に現れる(D-3)。自分自身を相手とする会話は、成立させない(UC-08 E2)。

**例外フロー**

- **E1 本文が正しくない**(空である、長さの上限を超える): システムは拒否する(R-3)。
- **E2 頻度の上限を超えた**: システムは拒否する(R-3)。
- **E3 会話が見つからない**: 会話が存在しない場合と、送信者が参加者でない場合に、システムは、同じ応答で拒否する(R-2)。1on1会話の最初のメッセージ(A1)で、相手が見つからない場合(UC-08 E1)も、同じ応答で拒否する。
- **E4 1on1会話の相手が退会している(フェーズ2)**: システムは拒否する(D-9)。
- **E6 送信を完了できなかった**(接続が切れている等): クライアントは、送信できなかったことを送信者に示す。送信者は、同じ本文を送り直せる。

**事後条件**

- 送信が完了したと示したメッセージは、サーバーが異常終了・再起動しても失われない。
- 会話の中のメッセージは、すべての参加者に、同じ順序で見える。
- 送信が完了したと示していないメッセージが、他の参加者に届いているかどうかは保証しない。送り直しによる重複の扱いは、仕様で定める。

**関連する水準**: AC-2、AC-6、SEC-4、SEC-5、OPS-2、PRV-4

### UC-10 会話の一覧を見る

- **フェーズ**: 1(1on1会話)、2(グループ会話)
- **アクター**: 利用者

**基本フロー**

1. 利用者は、アプリを開く。
2. システムは、利用者が参加する会話を、最後にメッセージが送られた時期が新しい順に、分割して示す(R-5)。メッセージのないグループと、最後のメッセージより後に利用者が参加したグループは、利用者が参加した時期で並べる(フェーズ2)。各会話には、1on1会話であれば相手の表示名とプレゼンスを、グループであればグループ名を示す。
3. 利用者は、会話を選んで開く(UC-11)。

**代替フロー**

- **A1 一覧を見ている間に変化があった**: 新しい会話が成立した、メッセージが届いた、参加関係を失った等の変化を、システムは、一覧に即時に反映する。
- **A2 未読のある会話を見分ける(フェーズ2)**: システムは、未読のある会話と、追加されてからまだ開いていないグループを、一覧の中で見分けられるように示す(UC-20)。

**事後条件**

- 一覧には、利用者が参加する会話だけが現れる。

**関連する水準**: AC-2、AC-6、PERF-2

### UC-11 会話の履歴を読む

- **フェーズ**: 1(1on1会話)、2(グループ会話)
- **アクター**: 利用者
- **事前条件**: 利用者が、その会話の参加者である

**基本フロー**

1. 利用者は、会話を開く。
2. システムは、最新のメッセージから遡って、一定の件数を示す(R-5)。各メッセージには、送信者と送信の日時を示す。グループでは、参加者の変化の記録(D-12)も、メッセージと同じ時系列の中に示す(フェーズ2)。
3. 利用者が過去へ遡ると、システムは、より古いメッセージを続けて示す。最も古いメッセージに達したら、それ以上ないことを示す。

**代替フロー**

- **A1 会話を開いている間にメッセージが届いた**: システムは、届いたメッセージを即時に示す(UC-09 基本フロー 3)。
- **A2 既読の位置が進む(フェーズ2)**: システムは、利用者が表示したメッセージまで、既読の位置を進める(UC-21)。
- **A3 指定した位置から開く(フェーズ2)**: 検索の結果から開いた場合(UC-25)、システムは、該当するメッセージとその前後を示す。利用者は、そこから、過去へも、より新しいメッセージへも、続けて読める(R-5)。

**例外フロー**

- **E1 会話が見つからない**: 会話が存在しない場合と、利用者が参加者でない場合に、システムは、同じ応答で拒否する(R-2)。

**事後条件**

- オフラインの間に届いたメッセージを含め、会話のすべてのメッセージを、遡って読める(グループについては D-7)。

**関連する水準**: AC-2、AC-5、PERF-2

### UC-12 プレゼンスを見る

- **フェーズ**: 1
- **アクター**: 利用者(見る側)。以下では、プレゼンスを見られる側の利用者をXとする

**基本フロー**

1. Xが、ログインしてアプリを開く。システムは、Xをオンラインとする。
2. システムは、Xと会話を共有する利用者のうちオンラインの人に、Xがオンラインになったことを即時に届ける。
3. 見る側の利用者は、会話の一覧と会話の中で、Xがオンラインかオフラインかを見る。
4. Xが、アプリを開いている端末をすべて閉じる、またはログアウトする。システムは、Xをオフラインとし、手順2と同じ宛先に届ける。

**代替フロー**

- **A1 Xが複数の端末でアプリを開いている**: 1つ以上の端末で開いている間、Xはオンラインである。ログイン状態が無効になった端末は、数えない(R-1)。
- **A2 Xの接続が切れた**: システムは、一定の時間のうちに再接続がなければ、Xをオフラインとする。時間は仕様で定める。

**例外フロー**

- **E1 会話を共有しない利用者のプレゼンスを求めた**: システムは、その利用者が存在しない場合と同じ応答で拒否する(R-2)。

**事後条件**

- プレゼンスは、会話を共有する利用者にのみ見える(D-2)。
- サーバーが再起動した場合、プレゼンスは、各利用者の再接続によって正しい状態に戻る。

**関連する水準**: AC-6、AC-7、PRV-2、PERF-3

### UC-13 切断から復帰する

- **フェーズ**: 1
- **アクター**: 利用者
- **事前条件**: 利用者がアプリを開いている間に、サーバーとの接続が切れた

**基本フロー**

1. クライアントは、接続が切れたことを検知し、利用者に示す。
2. クライアントは、再接続を試みる。
3. 再接続すると、クライアントは、切断中に届いたメッセージを取得して示し、接続が戻ったことを利用者に示す。フェーズ2以降は、切断中に生じたその他の変化(未読、既読の位置、メッセージの編集・削除、リアクション、参加関係とその記録)も、現在の状態に合わせる。

**代替フロー**

- **A1 切断中にログイン状態が無効になった**: システムは、ログインを求める(R-1)。
- **A2 再接続できない**: クライアントは、接続が切れていることを示し続け、再接続を試み続ける。試みる間隔は仕様で定める。
- **A3 通話中に接続が切れた(フェーズ3)**: UC-31 A1に従う。

**事後条件**

- 切断中に届いたメッセージは、欠けることも重複することもなく、会話に示される。
- 切断中に利用者が行おうとした操作は、行われていない(UC-09 E6)。

**関連する水準**: OPS-2、AC-6

### UC-14 グループを作成する

- **フェーズ**: 2
- **アクター**: 利用者

**基本フロー**

1. 利用者は、グループ名を入力する。追加するメンバーを、併せて指定できる(相手を指定する手段は UC-08)。
2. システムは、グループを作成し、作成した利用者を管理者に、指定された利用者をメンバーにする。
3. グループは、参加者の会話の一覧に現れる。システムは、オンラインの参加者に即時に反映する。指定された利用者には、追加されたことを知らせる(UC-20 A3)。

**例外フロー**

- **E1 グループ名が正しくない**: システムは拒否する(R-3)。
- **E2 指定した利用者を追加できない**: UC-15 E2、E4に従う。グループは作成しない。
- **E3 上限を超えた**: システムは拒否する(R-3)。

**事後条件**

- 作成した利用者は、そのグループの管理者である(D-4)。

**関連する水準**: AC-4、SEC-5

### UC-15 グループにメンバーを追加する

- **フェーズ**: 2
- **アクター**: 利用者(管理者)
- **事前条件**: 利用者が、そのグループの管理者である

**基本フロー**

1. 管理者は、追加する利用者を特定する(UC-08)。
2. システムは、その利用者をグループのメンバーにする。
3. グループは、追加された利用者の会話の一覧に現れる。追加された利用者は、過去のメッセージを含めて、グループの履歴を読める(D-7)。既読の位置は、追加された時点から始め、それより前のメッセージは、未読として扱わない(D-11)。
4. システムは、追加を会話に記録し(D-12)、参加者の一覧に反映する。オンラインの参加者には、即時に反映する。
5. システムは、追加されたことを、追加された利用者に知らせる(UC-20 A3)。

**例外フロー**

- **E1 管理者でない**: システムは拒否する。利用者がグループの参加者でない場合は、R-2に従う。
- **E2 追加する利用者が見つからない**(退会している等): システムは拒否する(R-2)。
- **E3 既に参加者である**: システムは、その旨を示し、何も変えない。
- **E4 人数の上限に達している**: システムは拒否する(D-5)。
- **E5 頻度の上限を超えた**: システムは拒否する(R-3)。

**事後条件**

- 追加された利用者は、そのグループの参加者として、会話を利用できる。追加された利用者の承諾は要しない(D-4)。

**関連する水準**: AC-4、AC-6、SEC-5

### UC-16 グループからメンバーを除外する

- **フェーズ**: 2
- **アクター**: 利用者(管理者)
- **事前条件**: 利用者が、そのグループの管理者である

**基本フロー**

1. 管理者は、メンバーを選び、除外する。
2. システムは、そのメンバーの参加関係を解消する。
3. グループは、除外された利用者の会話の一覧から消える。システムは、以後、そのグループの情報を、除外された利用者に届けない(R-4)。
4. システムは、除外を会話に記録し(D-12)、参加者の一覧に反映する。残る参加者のうちオンラインの人には、即時に反映する。

**代替フロー**

- **A1 除外された利用者が、そのグループの通話に参加している(フェーズ3)**: システムは、その利用者を通話から外す(UC-31 A2)。

**例外フロー**

- **E1 管理者でない**: システムは拒否する。利用者がグループの参加者でない場合は、R-2に従う。
- **E2 対象が参加者でない**: システムは拒否する。
- **E3 自分自身を指定した**: システムは拒否する。管理者は、退出(UC-17)を使う。

**事後条件**

- 除外された利用者は、そのグループを読むことも書くこともできない。
- 除外された利用者のメッセージとリアクションは、その利用者の表示名とともに、グループに残る(D-2、D-7)。除外された利用者は、これらを編集・削除、取り消しできない。
- 除外された利用者の既読の位置は、削除する。再び追加された場合は、新たに追加された場合と同じく扱う(UC-15)。

**関連する水準**: AC-2、AC-4、AC-6

### UC-17 グループから退出する

- **フェーズ**: 2
- **アクター**: 利用者(グループの参加者)

**基本フロー**

1. 利用者は、グループからの退出を求める。
2. システムは、利用者の参加関係を解消する。
3. グループは、利用者の会話の一覧から消える。
4. システムは、退出を会話に記録し(D-12)、参加者の一覧に反映する。残る参加者のうちオンラインの人には、即時に反映する。

**代替フロー**

- **A1 退出する利用者が管理者である**: システムは、残る参加者のうち、参加した時期が最も古い人を管理者にする(D-6)。管理者の変更も、会話に記録する(D-12)。
- **A2 退出する利用者が最後の参加者である**: システムは、グループとそのメッセージを、保管データから削除する(D-6)。
- **A3 そのグループの通話に参加している(フェーズ3)**: システムは、利用者を通話から外す(UC-31 A2)。

**事後条件**

- UC-16の事後条件と同じ。

**関連する水準**: AC-2、AC-4、AC-6、PRV-1

### UC-18 グループ名を変更する

- **フェーズ**: 2
- **アクター**: 利用者(管理者)
- **事前条件**: 利用者が、そのグループの管理者である

**基本フロー**

1. 管理者は、グループ名を書き換える。
2. システムは、入力を検証して保存し、参加者に反映する。

**例外フロー**

- **E1 管理者でない**: システムは拒否する。利用者がグループの参加者でない場合は、R-2に従う。
- **E2 グループ名が正しくない**: システムは拒否する(R-3)。

**事後条件**

- グループ名の変更は、会話に記録しない(D-12)。

**関連する水準**: AC-4、SEC-4

### UC-19 管理者を譲渡する

- **フェーズ**: 2
- **アクター**: 利用者(管理者)
- **事前条件**: 利用者が、そのグループの管理者である

**基本フロー**

1. 管理者は、メンバーを選び、管理者を譲渡する。
2. システムは、選ばれたメンバーを管理者にし、元の管理者をメンバーにする。
3. システムは、管理者の変更を会話に記録し(D-12)、参加者の一覧に反映する。オンラインの参加者には、即時に反映する。

**例外フロー**

- **E1 管理者でない**: システムは拒否する。利用者がグループの参加者でない場合は、R-2に従う。
- **E2 対象が参加者でない**: システムは拒否する。

**事後条件**

- グループの管理者は、常に1人である(D-4)。

**関連する水準**: AC-4

### UC-20 新着を把握する

- **フェーズ**: 2
- **アクター**: 利用者
- **事前条件**: 利用者が、アプリを開いている

**基本フロー**

1. 利用者が開いていない会話(別の会話を開いている場合を含む)に、メッセージが届く。
2. システムは、メッセージが届いたことを、利用者に即時に知らせる。会話の一覧では、その会話に未読があることを示す(UC-10 A2)。
3. 利用者がその会話を開いてメッセージを表示すると、未読の表示が消える(UC-21)。

**代替フロー**

- **A1 アプリを開いていない間に届いた**: 利用者は、次にアプリを開いたとき、会話の一覧で未読のある会話を見分ける。システムは、アプリの外へは知らせない。
- **A2 複数の端末でアプリを開いている**: 1つの端末で読むと、他の端末でも未読の表示が消える。
- **A3 グループに追加された**: システムは、追加された利用者がアプリを開いていれば、追加されたことを即時に知らせる。追加されたグループは、その利用者が最初に開くまで、未読のある会話と同じく、会話の一覧の中で見分けられるように示す(UC-10 A2)。グループの作成時に指定された利用者(UC-14)も、同じく扱う。

**事後条件**

- 自分が送ったメッセージ、メッセージの編集、リアクション、参加者の変化の記録(D-12)は、未読を生じさせない。
- 未読のメッセージが削除された場合、そのメッセージは未読から除かれる。

**関連する水準**: AC-2、AC-6

### UC-21 既読を確かめる

- **フェーズ**: 2
- **アクター**: 利用者(読む側、確かめる側)

**基本フロー**

1. 読む側の利用者は、会話を開き、メッセージを表示する。
2. システムは、その会話での読む側の既読の位置を、表示したメッセージまで進める。読む側の未読は、これに合わせて減る(UC-20)。
3. 1on1会話では、システムは、既読の位置が進んだことを、オンラインである相手に即時に届ける。
4. 確かめる側の利用者は、1on1会話の中で、自分のメッセージを相手がどこまで読んだかを見る。

**代替フロー**

- **A1 既に読んだ位置より前のメッセージを表示した**: 既読の位置は変わらない(後戻りしない)。
- **A2 グループである**: システムは、手順2までを行う。既読の位置は、他の参加者に見せず、届けない(D-11)。

**事後条件**

- 1on1会話の既読の位置は、その会話の2人にのみ見える。グループの既読の位置は、本人にのみ見える(D-11)。
- グループから退出・除外された利用者と、退会した利用者の既読の位置は、削除する。

**関連する水準**: AC-2、AC-6、PRV-2

### UC-22 メッセージを編集する

- **フェーズ**: 2
- **アクター**: 利用者(送信者)
- **事前条件**: 利用者が、対象のメッセージの送信者であり、その会話の参加者である

**基本フロー**

1. 送信者は、自分のメッセージを選び、本文を書き換える。
2. システムは、本文を検証して置き換え、編集前の本文を保管データから消す。
3. システムは、編集後の本文と、編集済みであることを、参加者に反映する。オンラインの参加者には、即時に反映する。

**例外フロー**

- **E1 自分のメッセージでない**: システムは拒否する。
- **E2 メッセージが削除されている**: システムは拒否する。
- **E3 本文が正しくない**(空である、長さの上限を超える): システムは拒否する(R-3)。フェーズ4以降、ファイルを添えたメッセージは、本文を空にできる(UC-33)。
- **E4 メッセージが見つからない**: メッセージが存在しない場合と、利用者がその会話の参加者でない場合(退出・除外された後を含む)に、システムは、同じ応答で拒否する(R-2)。
- **E5 1on1会話の相手が退会している**: UC-09 E4と同じく拒否する(D-9)。
- **E6 頻度の上限を超えた**: システムは拒否する(R-3)。

**事後条件**

- 編集前の本文は、他の利用者から見えず、保管データにも残らない。
- 編集済みであることは、会話に表示して残る。
- 編集は、未読を生じさせない。検索(UC-25)は、編集後の本文を対象とする。

**関連する水準**: AC-2、AC-3、PRV-5、SEC-4、SEC-5

### UC-23 メッセージを削除する

- **フェーズ**: 2
- **アクター**: 利用者(送信者)
- **事前条件**: 利用者が、対象のメッセージの送信者であり、その会話の参加者である

**基本フロー**

1. 送信者は、自分のメッセージを選び、削除する。
2. システムは、メッセージの本文と、そのメッセージに付いたリアクションを、保管データから消す。フェーズ4以降は、メッセージに添えたファイルも消す。
3. システムは、削除されたメッセージがあったことを会話に残し、参加者に反映する。オンラインの参加者には、即時に反映する。

**例外フロー**

- **E1 自分のメッセージでない**: システムは拒否する。グループの管理者も、他の参加者のメッセージは削除できない。
- **E2 既に削除されている**: システムは、何も変えない。
- **E3 メッセージが見つからない**: UC-22 E4と同じ。

**事後条件**

- 削除は、元に戻せない。
- 削除されたメッセージの本文は、他の利用者から見えず、保管データにも残らない。検索(UC-25)にも現れない。
- 1on1会話の相手が退会した後も、自分のメッセージは削除できる(D-9)。

**関連する水準**: AC-2、AC-3、PRV-5、PRV-7

### UC-24 リアクションする

- **フェーズ**: 2
- **アクター**: 利用者
- **事前条件**: 利用者が、その会話の参加者である

**基本フロー**

1. 利用者は、会話の中のメッセージを選び、リアクションを付ける。
2. システムは、リアクションを保管し、付けた利用者とともに、参加者に反映する。オンラインの参加者には、即時に反映する。

リアクションとして選べる種類は、仕様で定めます。

**代替フロー**

- **A1 リアクションを取り消す**: 利用者は、自分が付けたリアクションを取り消す。システムは、リアクションを消し、参加者に反映する。

**例外フロー**

- **E1 メッセージが削除されている**: システムは拒否する。
- **E2 同じ種類のリアクションを、既に付けている**: システムは、何も変えない。
- **E3 メッセージが見つからない**: UC-22 E4と同じ。
- **E4 1on1会話の相手が退会している**: UC-09 E4と同じく拒否する(D-9)。
- **E5 頻度の上限を超えた**: システムは拒否する(R-3)。

**事後条件**

- リアクションは、未読を生じさせない。
- 他の利用者が付けたリアクションは、取り消せない。
- グループから退出・除外された利用者が付けたリアクションは、付けた利用者の表示名とともに残る(D-2、D-7)。

**関連する水準**: AC-2、AC-6、PRV-2、SEC-5

### UC-25 メッセージを検索する

- **フェーズ**: 2
- **アクター**: 利用者

**基本フロー**

1. 利用者は、探したい語句を入力する。
2. システムは、利用者が参加する会話のメッセージのうち、本文に語句を含むものを、新しい順に、分割して示す(R-5)。各結果には、会話、送信者、送信の日時を示す。
3. 利用者は、結果を選び、その会話の該当する位置を開く(UC-11)。

語句の一致の仕方(大文字と小文字の区別など)は、仕様で定めます。

**代替フロー**

- **A1 該当するメッセージがない**: システムは、ないことを示す。

**例外フロー**

- **E1 語句が正しくない**(空である、長さの上限を超える): システムは拒否する(R-3)。
- **E2 頻度の上限を超えた**: システムは拒否する(R-3)。

**事後条件**

- 結果には、利用者が現に参加する会話のメッセージだけが現れる。退出・除外されたグループのメッセージと、削除されたメッセージは現れない。参加者の変化の記録(D-12)も現れない。
- 結果に示す送信者は、会話の中での見え方と同じである(退会した利用者は、削除済みユーザーの表示となる。UC-28)。

**関連する水準**: AC-2、AC-5、PERF-2、SEC-5

### UC-28 退会する

- **フェーズ**: 2
- **アクター**: 利用者

**基本フロー**

1. 利用者は、退会を求める。
2. システムは、利用者が本人であることを確かめ直す(手段は仕様で定める)。
3. システムは、他の利用者との会話に残る自分のメッセージを、削除するか残すかを尋ねる。併せて、残す場合は、本文に書かれた個人情報が残ることを示す。
4. 利用者は、削除するか残すかを選び、退会を確定する。
5. システムは、次を行う。
   - その利用者のすべてのログイン状態を無効にする。その利用者に発行済みの、連絡先の確認・再設定のための資格も、無効にする。
   - その利用者を、参加するすべてのグループから外す。管理者である場合と、最後の参加者である場合は、UC-17 A1、A2と同じく扱う。グループから外れたことは、退出として会話に記録する(D-12)。
   - 選択に従い、その利用者のメッセージを削除する、または、送信者を削除済みユーザーの表示に置き換える。参加者の変化の記録に現れるその利用者は、選択に依らず、削除済みユーザーの表示に置き換える(D-12)。
   - 相手が既に退会している1on1会話を、選択に依らず、メッセージとともに削除する(D-9)。
   - アカウント、プロフィール、連絡先、認証に用いる秘密、リアクション、既読の位置を削除する。
6. システムは、手順5の結果を、他の利用者に反映する。

削除するか残すかを選べる単位(すべての会話を一括か、会話ごとか)は、フェーズ2の設計で定めます。

**代替フロー**

- **A1 通話に参加している(フェーズ3)**: システムは、利用者を通話から外す(UC-31 A2)。

**例外フロー**

- **E1 本人であることを確かめられない**: システムは拒否する。連続した失敗は、UC-02 E2と同じく制限する。
- **E2 確定の前に取りやめた**: 何も変わらない。

**事後条件**

- 退会は、元に戻せない。
- 対象となるメッセージは、その利用者が送信したすべてのメッセージである。過去に退出・除外されたグループに残るものを含む(D-7)。フェーズ4以降は、メッセージに添えたファイルを含む。
- 削除を選んだメッセージは、UC-23と同じく、本文が保管データから消え、削除されたメッセージがあったことが会話に残る。その表示から、退会者を識別できない。
- 他の利用者の画面と保管データから、退会者を識別できない(残すことを選んだメッセージの本文を除く)。
- 退会者との1on1会話は、相手の一覧に残る(D-9)。相手が既に退会している1on1会話は、保管データに残らない。
- 退会者が使っていた識別名と連絡先は、再び登録に使える。
- バックアップとログに残るデータは、それぞれの保持期間まで残る(PRV-7)。

**関連する水準**: AC-3、AC-6、SEC-3、PRV-6、PRV-7

## フェーズ3

通話に関する共通の前提は、次の通りです。

- 通話は、会話の中で始め、その会話の参加者だけが参加できる。1つの会話で同時に行える通話は1つとする。
- 利用者は、同時に1つの通話にのみ参加できる。
- 通話は、参加している人が居なくなった時点で終了する。
- 通話の音声(フェーズ4以降は映像と画面を含む)は、保存しない(PRV-4)。通話があったことの記録は、会話に残さない。
- 1通話あたりの参加人数の上限は、フェーズ3の仕様で定める(企画書「仕様以降で決める事項」)。

### UC-29 通話を始める

- **フェーズ**: 3
- **アクター**: 利用者(開始者)
- **事前条件**: 開始者が、その会話の参加者である。その会話で、通話が行われていない

**基本フロー**

1. 開始者は、会話の中で、通話を始める。
2. システムは、通話を作り、開始者を参加させる。
3. システムは、その会話の他の参加者のうち、アプリを開いている人に、通話が始まったことを即時に知らせる。
4. システムは、会話の中に、通話が行われていることと、通話に参加している人を示す。

**代替フロー**

- **A1 その会話で、既に通話が行われている**: 開始者は、その通話に参加する(UC-30)。

**例外フロー**

- **E1 会話が見つからない**: UC-09 E3と同じ。
- **E2 1on1会話の相手が退会している**: UC-09 E4と同じく拒否する(D-9)。
- **E3 開始者が、他の通話に参加している**: システムは拒否する。
- **E4 端末で音声を使えない**(機器がない、利用者が使用を許可しない): クライアントは、始められないことを示す。
- **E5 頻度の上限を超えた**: システムは拒否する(R-3)。

**事後条件**

- アプリを開いていない参加者には、通話の開始は知らされない。通話が続いている間にアプリを開いた参加者は、会話の中の表示から通話に気付き、参加できる。

**関連する水準**: AC-2、AC-6、SEC-2、SEC-5、PRV-4

### UC-30 通話に参加する

- **フェーズ**: 3
- **アクター**: 利用者
- **事前条件**: 利用者が、その会話の参加者である。その会話で、通話が行われている

**基本フロー**

1. 利用者は、通話の開始の知らせ、または会話の中の表示から、通話に参加する。
2. システムは、利用者を通話に参加させる。利用者と、通話の他の参加者は、互いの音声を聞ける。
3. システムは、通話に参加している人の表示に、利用者を加える。

**代替フロー**

- **A1 参加しない**: 利用者は、知らせに応じない。システムは、応じなかったことを、通話の参加者に知らせない。

**例外フロー**

- **E1 通話が既に終了している**: システムは、終了していることを示す。
- **E2 通話の参加人数が上限に達している**: システムは拒否する。
- **E3 会話が見つからない**: UC-09 E3と同じ。
- **E4 利用者が、他の通話に参加している**: システムは拒否する。
- **E5 端末で音声を使えない**: UC-29 E4と同じ。
- **E6 通話に接続できない**(端末のネットワークの条件による等): クライアントは、参加できなかったことを示す。

**事後条件**

- 通話の音声は、通話に参加している人にのみ届く。

**関連する水準**: AC-2、AC-6、SEC-2、PERF-1、PRV-2、PRV-4

### UC-31 通話から抜ける

- **フェーズ**: 3
- **アクター**: 利用者(通話の参加者)

**基本フロー**

1. 利用者は、通話から抜ける。
2. システムは、利用者と他の参加者の間の音声のやり取りを止め、通話に参加している人の表示から、利用者を除く。
3. 通話に参加している人が居なくなった場合、システムは、通話を終了し、会話の中の通話の表示を消す。

**代替フロー**

- **A1 接続が切れた**: システムは、一定の時間のうちに利用者が通話に戻らなければ、利用者が抜けたものとして扱う。時間は仕様で定める。
- **A2 参加関係を失った**(グループからの退出・除外、退会): システムは、利用者を通話から外す。
- **A4 通話に使っている端末のログイン状態が無効になった**(ログアウト、認証に用いる秘密の変更・再設定、有効期限): システムは、利用者を通話から外す(R-1)。利用者は、ログインし直せば、再び参加できる。

**事後条件**

- 抜けた利用者には、通話の音声が届かない。
- 通話が続いている場合、抜けた利用者は、再び参加できる(UC-30)。A2の場合を除く。

**関連する水準**: AC-6、PRV-4

### UC-32 自分の音声を止める・再開する

- **フェーズ**: 3
- **アクター**: 利用者(通話の参加者)

**基本フロー**

1. 利用者は、自分の音声を止める。
2. システムは、利用者の音声を他の参加者に届けるのをやめ、止めていることを、通話の参加者に示す。
3. 利用者は、音声を再開する。システムは、利用者の音声を再び届け、表示を戻す。

**事後条件**

- 止めている間、利用者の音声は、他の参加者に届かない。利用者は、他の参加者の音声を聞ける。

**関連する水準**: PRV-2

## フェーズ4(拡張)

### UC-33 ファイルを共有する

- **フェーズ**: 4
- **アクター**: 利用者(送信者、受け取る側)
- **事前条件**: 利用者が、その会話の参加者である

**基本フロー**

1. 送信者は、会話の中でファイルを選び、送信する。本文を添えてもよい。
2. システムは、ファイルの大きさと種類を検証して保管し、ファイルを添えたメッセージとして、参加者に届ける(UC-09 基本フロー 2〜4と同じ)。
3. 受け取る側の利用者は、会話の中から、ファイルを取得する。

**代替フロー**

- **A1 ファイルを削除する**: 送信者は、ファイルを添えたメッセージを削除する(UC-23)。システムは、ファイルを保管データから消す。

**例外フロー**

- **E1 ファイルの大きさが上限を超える、または種類が許されていない**: システムは拒否する(R-3)。
- **E2 送信を完了できなかった**: UC-09 E6と同じ。
- **E3 メッセージを送れない状態にある**: UC-09 E2〜E4と同じ。
- **E4 参加者でない利用者が、ファイルの取得を試みた**: システムは、ファイルが存在しない場合と同じ応答で拒否する(R-2)。ファイルの所在を知っていても、取得できない。

**事後条件**

- ファイルを取得できるのは、取得する時点での、その会話の参加者だけである。
- 共有されたファイルは、受け取った利用者のブラウザで、プログラムとして実行されない。
- ファイルの内容は、検索(UC-25)の対象としない。
- 退会時の扱いは、メッセージと同じである(UC-28)。

**関連する水準**: AC-2、AC-5、SEC-2、SEC-5、SEC-9、PRV-4、PRV-5

### UC-34 画面を共有する

- **フェーズ**: 4
- **アクター**: 利用者(通話の参加者)
- **事前条件**: 利用者が、通話に参加している

**基本フロー**

1. 利用者は、見せる画面を選び、共有を始める。
2. システムは、その画面を通話の他の参加者に届け、誰が共有しているかを示す。
3. 利用者は、共有を止める。システムは、画面を届けるのをやめる。

**代替フロー**

- **A1 共有している利用者が、通話から抜けた**: システムは、共有を止める。
- **A2 共有が行われている通話に、後から参加した**: 参加した利用者にも、共有されている画面が見える。

**例外フロー**

- **E1 端末で画面の共有を使えない**(対応していない、利用者が使用を許可しない): クライアントは、始められないことを示す。
- **E2 同時に共有できる数の上限に達している**: システムは拒否する。上限は仕様で定める。

**事後条件**

- 共有された画面は、通話に参加している人にのみ届く。保存しない。

**関連する水準**: AC-2、AC-6、SEC-2、PRV-4

### UC-35 映像を使って通話する

- **フェーズ**: 4
- **アクター**: 利用者(通話の参加者)
- **事前条件**: 利用者が、通話に参加している

**基本フロー**

1. 利用者は、自分の映像を送り始める。
2. システムは、利用者の映像を、通話の他の参加者に届ける。
3. 利用者は、映像を止める。システムは、映像を届けるのをやめる。音声は、止めない限り届き続ける。

**代替フロー**

- **A1 通話の開始・参加と同時に、映像を送る**: 利用者は、UC-29、UC-30で、映像を送る状態で通話に入る。
- **A2 映像を送る参加者と、送らない参加者が混在する**: 映像を送らない参加者も、他の参加者の映像を見られ、音声でやり取りできる。

**例外フロー**

- **E1 端末で映像を使えない**(機器がない、利用者が使用を許可しない): クライアントは、映像を送れないことを示す。利用者は、音声だけで通話を続けられる。

**事後条件**

- 映像は、通話に参加している人にのみ届く。保存しない。

**関連する水準**: AC-2、AC-6、SEC-2、PERF-1、PRV-2、PRV-4
