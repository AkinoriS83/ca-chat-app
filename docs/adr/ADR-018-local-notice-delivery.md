# ADR-018 ローカルの開発環境で、案内を受け取る手段

- ステータス: active
- 作成日: 2026-11-27
- 対象: 登録とログイン([仕様](../specs/registration-and-login.md)「技術要素の決定」)

## Context

登録は、連絡先(メールアドレス)へ、確認のための案内を送ります(UC-01)。本スライスは、ローカルの開発環境に限って動かし、案内を、開発者の端末の外へ送りません(RL-D1、RL-37)。設置環境でメールを送信する手段の選定は、設置環境を扱うスライスに送られています(仕様「後続に送る事項」)。

本ADRは、ローカルの開発環境で、サーバーが案内を送り出す手段と、送り出した案内を、開発者と自動テストが受け取って読む手段を決定します。

選定の条件は、次の通りです(仕様「技術要素の決定」)。

- 案内が、開発者の端末の外へ送られない(RL-37)。案内を受け取る手段に、開発者の端末の外から到達できない(RL-38)。
- 開発者と自動テストが、案内を読める(RL-01)。
- 設置環境で使う送信の手段に、差し替えられる。
- すべての選定に共通する条件を満たす。

関連する受け入れ基準と規則は、次の通りです。

- 案内は、確認のための資格を含む。資格は、ログに出力しない(SEC-1、RL-33)。
- 案内を送れなかった場合、完了できなかったことを示し、出来事を記録する(RL-10)。
- 仮実装を、新たに加えない(`CLAUDE.md`「仮実装」)。

## Decision

- サーバーは、案内を、SMTP で送る。送信には、Go の標準ライブラリ(net/smtp)を使う。案内の組み立て(ヘッダーと本文の符号化)も、標準ライブラリ(mime など)で行う。
- 案内は、書式を持たないテキストとする。宛先のほかに、訪問者が入力した内容を含めない(RL-11)。宛先は、入力の規則を満たした連絡先に限られるため、ヘッダーとして解釈される文字を含まない(仕様「入力の規則」)。
- 送信は、ポートの背後に置く。ポートを実装する adapter が、SMTP を扱う([ADR-005](ADR-005-layer-structure.md))。
- ローカルの開発環境では、送り先の SMTP のサーバーとして、Mailpit を動かす。Mailpit は、受け取ったメールを、外へ送らずに溜め、画面と HTTP の API で読めるようにする、開発用の道具である。
  - 保管先と同じく、Docker Compose で、コンテナとして動かす([ADR-007](ADR-007-local-development-environment.md))。イメージの版は、定義の中で固定する(`axllent/mailpit:v1.34.0`)。
  - SMTP の待ち受け先(1025番)と、画面と API の待ち受け先(8025番)は、どちらも、127.0.0.1 に限って公開する。
  - 受け取ったメールを、他のサーバーへ中継する機能は、設定しない。新しい版の確認の機能は、無効にする。
- 開発者は、Mailpit の画面で、案内を読む。自動テストは、Mailpit の HTTP の API で、宛先を指定して、案内を読む。ポートの差し替えで足りるテストは、差し替える([ADR-006](ADR-006-automated-testing.md))。テストごとの手段は、詳細設計で定める。
- SMTP のサーバーの接続先と、送信元のアドレスは、設定で与える。

設定の名前、案内の文面、Mailpit のポートの番号を変える手段は、詳細設計で定めます。

### 選定の条件の確認

Mailpit の版、ライセンス、待ち受け先の既定の値、API、設定の項目は、2026-11-27 に、Mailpit のリポジトリ(v1.34.0。2026-11-17 に公開)と、文書で確かめました。開発者の端末で動かしての確認は、まだ行っていません(実装の最初に行う)。

| 条件 | 確認 |
|---|---|
| 案内が、開発者の端末の外へ送られない(RL-37) | サーバーが送る先は、127.0.0.1 の Mailpit だけである。Mailpit は、中継を設定しない限り、受け取ったメールを、どこへも送らない |
| 案内を受け取る手段に、端末の外から到達できない(RL-38) | Mailpit の2つのポートを、127.0.0.1 に限って公開する。保管先のポートと、同じ形である(ADR-007) |
| 開発者と自動テストが、案内を読める(RL-01) | 開発者は、ブラウザで、Mailpit の画面を開く。自動テストは、API(メールの一覧、検索、1通の取得)で読む |
| 設置環境で使う送信の手段に、差し替えられる | 送信は、ポートの背後にある。設置環境の手段が SMTP を受け付ける場合は、接続先の設定を変える。受け付けない場合は、ポートの実装を加える。どちらも、内側の層を変えない |
| 後続フェーズの妨げにならない | 再設定と、連絡先の変更の案内(UC-04、UC-06)も、同じポートと手段で送れる |
| 複数サーバー構成への移行を妨げない(PERF-3) | 送信は、サーバーに状態を持たない |
| ライセンスが、MITライセンスでの公開と両立する | Mailpit(MIT)。開発の時点で動かす道具であり、成果物に含まれない。サーバーに、依存物は加わらない |
| 個人データとメッセージを、外部のサービスへ送信しない(PRV-3) | 外部のメールのサービスを使わない。Mailpit は、開発者の端末の上で動く |
| 検証にかける費用を、小さく抑えられる | 無償で使える |

## 検討した代替案

| 代替案 | 採らなかった理由 |
|---|---|
| 案内を、ファイルに書き出す adapter を作る(SMTP を使わない) | 動かすものが増えず、テストは、ファイルを読むだけで済む。ローカルの開発環境のためだけの実装になり、設置環境では、送信の adapter を、別に作ることになる。実質は、仮実装を加えることに当たる。送信に失敗した場合(RL-10)も、実際の送信の経路では、確かめられない |
| 案内を、サーバーのログに出力する | 最も簡素である。確認のための資格が、ログに出力される(SEC-1、RL-33 に反する) |
| 案内を、サーバーのメモリに溜め、読むための操作を、サーバーに設ける | 動かすものが増えない。他人の連絡先に宛てた案内を、資格とともに読める操作になる。設置環境に残ると、登録の確認が、意味を失う |
| 外部のメールのサービスの、検証用の環境を使う | 設置環境に近い経路を、確かめられる。案内が、開発者の端末の外へ出る(RL-37 に反する)。メールを送信する手段の選定は、設置環境を扱うスライスに送られている |
| MailHog | 同じ用途の道具であり、広く使われてきた。開発が、長く止まっている。Mailpit は、同じ使い方(SMTP で受け、API で読む)ができ、開発が続いている |
| smtp4dev、MailCatcher | 条件は満たせる。Mailpit を選んだのは、単一の実行ファイルのコンテナで、API の定義が公開されており、開発が続いているためである |
| メールの送信のライブラリ(wneessen/go-mail など)を使う | 添付、複数の形式の本文、接続の細かな制御を備える。本スライスの案内は、テキストの本文だけであり、標準ライブラリで足りる([ADR-001](ADR-001-language-and-libraries.md))。net/smtp は、機能の追加を止めているが、使う機能は、備わっている |

## Consequences

- ローカルの開発環境で動かすコンテナが、1つ増える。保管先を起動する手順が、Mailpit も起動する。手順書と、アーキテクチャ概要「実行環境の構成」を更新する(実装の中で)。
- SMTP を通るテストと、E2Eテストは、Mailpit が起動していることを要する。Mailpit は、テストの間で共有されるため、テストは、宛先の連絡先を、テストごとに変えて、案内を見分ける。
- Mailpit は、受け取ったメールを、コンテナの中に保持する。コンテナを作り直すと、消える。開発者が登録に使った連絡先と、確認のための資格が、その間、Mailpit に残る。到達できるのは、開発者の端末の中だけである(RL-38)。
- Mailpit の画面と API は、認証を持たない。127.0.0.1 に限って公開することが、到達を制限する、ただ1つの手段である。Windows の側の 127.0.0.1 にも現れる(ADR-007 の Consequences)。
- 境界要素が、1つ増える(案内を送るポート)。application のテストと、送れなかった場合のテスト(RL-10)は、このポートを差し替える。
- 設定が、2つ増える(SMTP のサーバーの接続先、送信元のアドレス)。ローカルの開発環境の値は、秘密ではない。`.env.example` と、手順書に加える。
- ローカルの開発環境の SMTP は、暗号化も、認証も、行わない。設置環境での、暗号化、認証、送信元のドメインの設定、到達の確認(企画書「リスク」14)は、メールを送信する手段の選定とともに、設置環境を扱うスライスで定める。
- 案内に載せる、登録を続けるためのアドレスは、アプリのオリジン(既存の設定)から組み立てる。載せる形は、詳細設計で定める([ADR-014](ADR-014-authentication-method.md) の Consequences)。
- 「案内を送った」は、SMTP のサーバーに引き渡せたことを指す(仕様「登録する」)。引き渡せなかった場合に、サーバーは、完了できなかったことを示す。送信を待つ時間の上限は、詳細設計で定める。
