# ADR-016 ログイン状態、登録の申し込み、上限の計数を保持する先

- ステータス: active
- 作成日: 2026-11-27
- 対象: 登録とログイン([仕様](../specs/registration-and-login.md)「技術要素の決定」)

## Context

本スライスは、サーバーが保持する状態を、3種類、加えます。

| 状態 | 内容 | 仕様が求めること |
|---|---|---|
| ログイン状態 | 資格の要約、利用者、有効期限、ログイン状態の識別子([ADR-014](ADR-014-authentication-method.md)) | サーバーを再起動した後も、有効期限まで保たれる(RL-21)。ログアウトで、無効になる(RL-17) |
| 登録の申し込み | 連絡先、確認のための資格の要約、有効期限 | サーバーを再起動した後に、完了できる(RL-21)。同じ連絡先での再度の申し込みで、以前の資格が使えなくなる(RL-04)。期限を過ぎると、連絡先とともに消える(RL-09)。同じ資格での完了が同時に行われても、完了するのは1つである(RL-05) |
| 上限の計数 | 送信元、連絡先、利用者ごとの、直近の回数(仕様「上限」) | サーバーの再起動で、失われてよい(仕様「上限」) |

選定の条件は、次の通りです(仕様「技術要素の決定」)。

- RL-09、RL-21 を満たせる。
- 1つのサーバーの中だけで保持する状態は、内側の層が定義するインターフェイスの背後(外側の層)に置く(RL-39)。
- 複数サーバー構成への移行を妨げない(PERF-3)。
- すべての選定に共通する条件を満たす。

利用者(連絡先、識別名、表示名、保管した秘密)は、[ADR-004](ADR-004-data-store.md) の通り、保管先(PostgreSQL)に置きます。本ADRの対象では、ありません。

## Decision

- ログイン状態と、登録の申し込みは、保管先(PostgreSQL)に置く。
  - 資格は、要約で引く。要約に、一意性の制約を置く(ADR-014)。
  - 登録の申し込みは、連絡先ごとに、1つだけを持つ。再度の申し込みは、以前のものを置き換える。
  - 登録の完了(申し込みを使用済みにすることと、利用者を作ること)は、1つのトランザクションで行う([ADR-012](ADR-012-transaction-boundary.md) のポートを使う)。同時の完了と、識別名の重複は、保管先の制約とトランザクションで、1つに保つ(RL-05、RL-07)。
  - 有効かどうかは、照会の時点で、有効期限と比べて判定する。期限を過ぎた行を消す時点と仕組みは、詳細設計で定める(仕様「後続に送る事項」)。
- 上限の計数は、サーバーのメモリに置く。ポートを実装する adapter の中に保持し、application が定義するポートの背後とする(RL-39)。
  - ポートの操作は、ユースケースの用語で定義する(数える、上限に達しているかを確かめる、0に戻す)。数えることと、確かめることを、分けて呼ばせる場合も、同時の要求で、上限を超えて受け付けない形にする。
  - 数える時間を過ぎた計数は、メモリから消す。仕組みは、詳細設計で定める。
- 新しい保管の仕組み(キーバリュー型の保管先など)は、加えない。

### 選定の条件の確認

| 条件 | 確認 |
|---|---|
| RL-21(再起動の後も、保たれる) | ログイン状態と、登録の申し込みは、PostgreSQL の、確定したトランザクションとして残る(ADR-004) |
| RL-09(期限を過ぎた申し込みが、消える) | 有効期限を、行に持つ。期限を過ぎた行を、条件を指定して消せる。連絡先は、申し込みの行にだけあり、行とともに消える |
| RL-39(1つのサーバーの中だけで保持する状態) | 上限の計数だけが、これに当たる。ポートを実装する adapter の中に置く。ログイン状態と接続の対応付けは、ADR-014 が、配信の adapter に置く |
| 複数サーバー構成への移行を妨げない(PERF-3) | ログイン状態と、登録の申し込みは、PostgreSQL に置くため、どのサーバーからも、同じ内容を引ける。一意性と、同時の完了は、保管先の制約とトランザクションで保つ。上限の計数は、サーバーごとになるため、複数サーバー構成では、ポートの実装を、共有の保管先を使うものに差し替える。内側の層は、変えない。本スライスでは、作らない |
| 後続フェーズの妨げにならない | 秘密の変更と再設定(UC-07、UC-04)が求める、利用者のすべてのログイン状態の無効化は、ログイン状態を、利用者から引いて行える。そのための操作は、先行して作らない |
| ライセンスが、MITライセンスでの公開と両立する | 依存物を加えない |
| 個人データとメッセージを、外部のサービスへ送信しない(PRV-3) | 既存の保管先と、サーバーのメモリだけを使う |
| 検証にかける費用を、小さく抑えられる | 費用は、生じない。動かすものも、増えない |

## 検討した代替案

| 代替案 | 採らなかった理由 |
|---|---|
| ログイン状態を、サーバーのメモリに置く | 操作のたびの、保管先への照会が要らない。サーバーの再起動で、すべての利用者がログアウトされ、RL-21 を満たせない。複数のサーバーで、共有できない |
| ログイン状態を、保持しない(自己完結型の資格) | ADR-014「検討した代替案」の通り |
| 上限の計数も、PostgreSQL に置く | 再起動の後も残り、複数のサーバーで、最初から共有できる。採らなかった理由は3つある。(1) 仕様は、再起動で失われてよいとしている。(2) 数える対象の要求のたびに、書き込みが生じる。拒否するための処理が、保管先に負荷をかける。(3) ログインの失敗は、登録されていない連絡先にも数える(仕様「上限」)。保管先に置くと、打ち間違えた連絡先や、連絡先の欄に誤って入力された値が、保管データとバックアップに残る(PRV-1。RL-D8 が、記録について避けたことと同じである) |
| キーバリュー型の保管先(Redis、Valkey など)を加えて、ログイン状態と計数を置く | 期限とともに消える値と、計数に合い、複数のサーバーで共有できる。想定規模では、PostgreSQL とメモリで足りる。動かすもの、バックアップと到達の制限(SEC-8)の対象、設置環境の費用が増える。複数サーバー構成で計数の共有が要るときに、計数のポートの実装として、選べる |
| 登録の申し込みを、保持しない(連絡先と期限を含め、署名した値を、確認のための資格にする) | 確認されていない連絡先を、保管せずに済む。一度だけ使えること(SEC-3)と、再度の申し込みで以前の資格を使えなくすること(RL-04)に、結局、サーバーが保持する状態が要る。鍵の管理も加わる(SEC-6) |

## Consequences

- 保管先に、利用者、ログイン状態、登録の申し込みの表が加わる。マイグレーションで加える([ADR-004](ADR-004-data-store.md))。
- 境界要素が増える見込みである(ログイン状態を保持するポート、登録の申し込みを保持するポート、上限を数えるポート。トランザクションの中で行える操作にも、加わる)。形は、詳細設計で定め、観察記録の計数の対象とする([ADR-008](ADR-008-observation-records.md))。
- 上限の計数は、サーバーを再起動すると、0に戻る。連絡先ごとのログインの拒否も、解ける。再起動を行えるのは、運営者だけである(仕様「上限」)。
- 連絡先ごとの計数は、登録されていない連絡先も含め、数える時間の間、サーバーのメモリに持つ。保管データ、バックアップ、ログには、残らない。
- 計数が占めるメモリは、数える時間の中に受け付けた、異なる送信元、連絡先、利用者の数に比例する。送信元ごとの上限が、1つの送信元から増やせる量を限る。
- 有効期限と、上限の時間の経過を、自動テストで確かめるために、時刻を得る手段を、差し替えられる形にする。保管先に置く期限の判定を、サーバーの時刻で行うか、保管先の時刻で行うかを含め、詳細設計で定める(仕様「後続に送る事項」)。保管先の時刻で判定すると、テストから時刻を進められない。期限に達した接続を閉じる時点([ADR-014](ADR-014-authentication-method.md) の Consequences)とも、食い違いうる。
- 期限を過ぎた行は、サーバーが動いている間に、一定の間隔で消す。サーバーを止めている間は、消えない。「期限から24時間以内に、保管データから消える」(仕様「登録する」、RL-09)は、サーバーが動いている間に成り立つ。起動の直後に、1回、消す。期限を過ぎた行は、残っている間も、照会の時点の判定によって、使えない(詳細設計のレビュー〈2026-11-27〉で、追記した)。
- ログイン状態と、登録の申し込みは、個人データに関わる。取得する個人データの一覧(RL-36)に、保管先として載せる。確認されていない連絡先は、期限まで、保管データに残る(RL-D7 の帰結と同じ)。
- 保管データを、バックアップから復元すると(OPS-5)、バックアップを取得した後に無効にしたログイン状態が、有効期限まで、有効に戻る。復元の手順で、ログイン状態を消すかどうかは、設置環境を扱うスライスで定める。
