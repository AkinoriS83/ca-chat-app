# ADR-022 PRでの検査とテストの自動実行と、マージの条件

- ステータス: active
- 作成日: 2026-11-27
- 対象: プロジェクト全体([ADR-006](ADR-006-automated-testing.md) が、別のADRに送った事項)

## Context

検査とテストは、開発者とAIが、ローカルの開発環境で、`make check` と `make e2e` を実行して確かめています([ADR-007](ADR-007-local-development-environment.md))。変更のたびに自動で実行する仕組み(CI)は、ADR-006 が、「必要になった時点で、別のADRで判断する」としています。

「登録とログイン」のスライスから、`main` への変更を、GitHub のPRで取り込みます。これを機に、検査とテストが通っていない変更を、`main` に取り込めないようにします。理由は、次の通りです。

- ローカルでの実行は、実行し忘れを防げない。`make e2e` は、`make check` に含まれず、画面と、サーバーとクライアントのつなぎに関わる変更のときに、手で実行する決まりである(`CLAUDE.md`「検査とテスト」)。
- ローカルでの成功は、開発者の端末の状態(追跡していないファイル、導入済みの道具、`.env`)に依りうる。リポジトリの内容だけから、成功することを確かめる手段がない。
- 依存規則の違反が0件であることは、マイルストーンの完了条件である(企画書「各マイルストーンに共通の完了条件」3、「リスク」9)。

本ADRは、自動で実行する手段、実行する範囲、マージの条件を決定します。

選定の条件は、次の通りです。

- `make check` と `make e2e` を、ローカルと同じ手順で実行できる。手順を、二重に定義しない。
- 依存物の版を固定する(WS-32)。秘密を、リポジトリに含めない(SEC-6、WS-34)。
- 変えてはならない前提(`CLAUDE.md`)と、RL-D1([「登録とログイン」の仕様](../specs/registration-and-login.md))の理由を損なわない。待ち受け先と、SMTP の接続先を、ループバックのアドレスの外に広げない。
- すべての選定に共通する条件(後続フェーズの妨げにならない、ライセンス、PRV-3、費用)を満たす。

確かめた事実は、次の通りです(2026-11-27)。

- リポジトリは、GitHub で公開している。`.github/` はなく、`main` に、ブランチの保護は設定されていない(`gh api` で確かめた)。
- GitHub の文書は、公開リポジトリでは、標準の GitHub-hosted ランナーを無償で使えるとしている(GitHub Docs「GitHub Actions billing」)。
- ブランチの保護は、既定では、管理者に適用されない。「Do not allow bypassing the above settings」を有効にすると、管理者にも適用される(GitHub Docs「About protected branches」)。
- GitHub の文書は、アクションの参照を、コミットのハッシュで固定することを勧めている(GitHub Docs「Secure use reference」)。
- 個人のアカウントの公開リポジトリで、必須のチェックを設定できることは、文書では確かめていない。設定の時点で確かめる。

## Decision

### 自動で実行する手段と、範囲

- GitHub Actions を使う。ワークフローは、`main` に向けたPRを作ったときと、PRのブランチを更新したときに、実行する。
- ジョブは、2つとする。どちらも、`Makefile` の手順を、そのまま呼ぶ。ワークフローには、検査とテストの内容を書かない。

| ジョブ | 実行する手順 | 確かめること |
|---|---|---|
| check | `make setup`、`make db-up`、`make check` | 生成したコードの差分、lint、依存規則と飛ばし禁止、サーバーとクライアントのテスト、秘密の検出 |
| e2e | `make setup`、`make db-up`、`make e2e` | サーバーとクライアントをつないだ動作(ADR-006「E2Eテストの範囲」) |

- E2Eテストを、含める。`make check` は、画面と、サーバーとクライアントのつなぎを確かめず、実行し忘れを拾う手段が、ほかにないためである。変更した置き場所によって、実行を省くことは、しない(「検討した代替案」)。
- ランナーは、標準の GitHub-hosted ランナー(Ubuntu。版を指定する)とする。
  - Go と Node.js の版は、`server/go.mod` と `client/.nvmrc` から取る。Go の道具の版は、`Makefile` が定める。
  - 保管先(PostgreSQL)と、案内を受け取る手段(Mailpit)は、ローカルと同じく、`compose.yaml` で起動する([ADR-004](ADR-004-data-store.md)、[ADR-018](ADR-018-local-notice-delivery.md))。
  - E2Eテストのブラウザは、Playwright が取得する Chromium とする。版は、`@playwright/test` の版で決まる。Chromium が要する OS のライブラリは、ランナーの上で導入する。
- `.env` は、ジョブの中で、`.env.example` から作る(`scripts/ci-env.sh`)。`PGPASSWORD` は、実行のたびに、無作為な値を生成して与える。値は、ランナーとともに消える。リポジトリにも、GitHub の Secrets にも、秘密を置かない。
- `secrets-scan` は、履歴を調べるため(WS-34)、リポジトリを、履歴の全体とともに取得する。

### ワークフローの安全

- 使うアクションは、GitHub が提供するもの(リポジトリの取得、Go と Node.js の導入)に限り、コミットのハッシュで固定する(WS-32)。
- ワークフローに与える権限は、リポジトリの内容の読み取りだけとする。ワークフローは、リポジトリに書き込まず、コメントも付けない。
- フォークからのPRにも、同じワークフローを、秘密なしで実行する(`pull_request` で起動する。`pull_request_target` は、使わない)。ワークフローは、秘密を持たないため、フォークのコードに渡るものはない。

### マージの条件

`main` に、ブランチの保護を設定します。

| 設定 | 値 | 理由 |
|---|---|---|
| 必須のチェック | check と e2e の、両方の成功 | 本ADRの目的 |
| マージの前に、ブランチを最新にすること | 求める | 確かめた内容と、取り込まれる内容を、一致させる。開発者が1名のため、最新にし直す手間は小さい |
| PRを経ること | 求める。承認は、求めない | `main` へ、直接にプッシュできないようにする。開発者が1名であり、自らのPRは、承認できない |
| 管理者による迂回 | 許さない | 許すと、リポジトリの所有者である開発者は、チェックが失敗していても、マージできる |

- 保護の設定は、GitHub の側にあり、リポジトリには記録されない。設定の内容と、設定する手順を、手順書(`README.md`)に記録する。
- チェックが失敗したときは、原因を直す。保護を外して、取り込まない(`CLAUDE.md`「テストと検査を、通すために緩めない」)。

### RL-D1 と、変えてはならない前提との関係

CIでは、サーバーが、ローカルの開発環境の外(GitHub のランナーの上)で起動します。サーバーのテストと、E2Eテストが、サーバーを起動するためです。これは、RL-D1 と、`CLAUDE.md`「変えてはならない前提」の理由を損なわないと判断します。

- 前提の理由は、秘密、資格、案内が、暗号化されていない経路を通ることである(SEC-2)。CIでも、待ち受け先と、SMTP の接続先は、ループバックのアドレスのままであり、通信は、1つのランナーの中に閉じる。RL-38 の検査(ループバックのアドレスでない待ち受け先では、起動しない)は、CIでも働く。
- ランナーの上にあるのは、テストが作ったデータだけである。実在の利用者の個人データとメッセージは、ない(PRV-3)。ランナーは、ジョブの終わりに破棄される。
- 利用できるサービスとして、動かすものではない。ランナーの上のサーバーに、ランナーの外から到達する経路は、設けない(企画書「リスク」6)。

`CLAUDE.md` の該当の箇所には、CIのランナーの扱いを、書き添えます。仕様(RL-D1)は、改めません。

### 選定の条件の確認

| 条件 | 確認 |
|---|---|
| ローカルと同じ手順で実行できる | ジョブは、`make` の手順だけを呼ぶ。保管先と Mailpit は、同じ `compose.yaml` で起動する |
| 依存物の版を固定する(WS-32) | アクションは、コミットのハッシュで固定する。ランナーの版を指定する。道具と依存物の版は、ローカルと同じ定義から取る |
| 秘密を、リポジトリに含めない(SEC-6) | 秘密を使わない。`PGPASSWORD` は、実行のたびに生成する |
| 後続フェーズの妨げにならない | 設置環境への配置(OPS-1)は、本ADRでは定めない。ワークフローは、検査とテストに限り、設置環境の構成を前提にしない |
| ライセンスが、MITライセンスでの公開と両立する | GitHub Actions は、サービスであり、成果物に含まれない。使うアクションのライセンスは、実装の時点で確かめ、手順書の一覧に載せる |
| 個人データとメッセージを、外部のサービスへ送信しない(PRV-3) | GitHub へ送られるのは、既に公開しているソースコードと、テストの出力である。テストのデータは、テストが作った値である |
| 検証にかける費用を、小さく抑えられる | 公開リポジトリでは、標準のランナーを無償で使える |

## 検討した代替案

| 代替案 | 採らなかった理由 |
|---|---|
| CIを設けず、ローカルでの実行を続ける | 仕組みが増えず、GitHub に依らない。実行し忘れと、端末の状態に依る成功を、防げない |
| Git のフック(プッシュの前)で、ローカルで実行する | GitHub に依らず、プッシュの前に気付ける。フックは、リポジトリの複製ごとに導入が要り、飛ばせるため、マージの条件にできない。開発者の端末は、メモリが少なく、プッシュのたびのE2Eテストは、重い |
| E2Eテストを、CIに含めない | 実行の時間が短く、不安定なテストで、マージが止まらない。サーバーとクライアントの食い違いを、マージの前に拾う手段が、手での実行だけになる |
| E2Eテストを、画面に関わる置き場所を変えたPRでだけ、実行する | 文書だけのPRで、時間がかからない。必須のチェックは、実行されなかった場合、待ちのまま残り、マージできなくなる。避けるには、ワークフローに、条件の分岐が要る。サーバーだけの変更でも、つなぎは壊れうる |
| 保管先と Mailpit を、ワークフローの定義(サービスコンテナ)で起動する | GitHub Actions の標準の方法である。版と起動の設定が、`compose.yaml` と二重になる |
| 開発者の端末を、ランナーにする(self-hosted) | ローカルと、同じ環境で動く。公開リポジトリでは、フォークからのPRが、開発者の端末でコードを実行しうる。端末が起動していない間は、マージできない |
| ほかのCIのサービスを使う | 機能に、大きな差はない。リポジトリとPRが GitHub にあり、別のサービスへの登録と連携が要る |
| `main` へのプッシュでも、実行する | マージの後の `main` を、確かめられる。ブランチを最新にすることを求めるため、マージされる内容は、PRで確かめた内容と同じである |
| 管理者による迂回を、許す | 緊急のときに、すぐ取り込める。許すと、条件が、開発者に対して働かない。運営しているサービスはなく、緊急の取り込みは、想定しない |
| 依存物の、既知の脆弱性の検査(SEC-7)を、CIに加える | 早く気付ける。SEC-7 は、フェーズの完了時に確かめると定められており、手段の選定は、その時点で行う |

## Consequences

- GitHub Actions が使えない間(障害など)は、`main` に取り込めない。
- PRごとに、実行の時間がかかる。かかる時間は、確かめていない。最初の実行で測り、手順書に記録する。
- E2Eテストは、再試行しない設定である(`retries: 0`)。不安定なテストが1つあると、マージが止まる。その場合も、再試行を加えて通さず、原因を直す。
- 文書だけを変えるPRでも、両方のジョブを実行する。
- CIで、依存規則の違反を検出しても、検査の記録(`docs/dependency-check-log.md`)には、残らない。追記は、ランナーとともに消えるためである。CIでの検出は、PRのチェックの失敗として残る。違反の件数を数えるとき([ADR-008](ADR-008-observation-records.md))は、検査の記録に加えて、失敗したチェックを確かめる必要がある。ローカルで `make check` を実行してから、プッシュする決まりは、変えない。
- ランナーの環境(OS、Docker の版)は、開発者の端末と異なる。ローカルで成功し、CIで失敗する、または、その逆がありうる。E2Eテストのブラウザは、開発者の端末では、導入済みの Chromium(`E2E_CHROMIUM_PATH`)であり、CIでは、Playwright が取得した Chromium である。
- アクションと、ランナーの版は、固定するため、手で更新する。自動で更新する仕組みは、設けない。
- テストの出力は、公開リポジトリでは、誰でも読める。テストとログが、秘密と資格を出力しないこと(RL-33)が、CIでも前提になる。
- ブランチの保護は、リポジトリの外にあり、雛形の利用者が、リポジトリを複製しても、引き継がれない。手順書に従って、設定し直す必要がある。
- 実装で、次の文書を直す。手順書(CIの内容、保護の設定)。アーキテクチャ概要(実行環境)。`CLAUDE.md`(「検査とテスト」「変えてはならない前提」)。
