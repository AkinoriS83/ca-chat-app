# ADR-020 ポートを実装する adapter が呼んでよい、domain の判定

- ステータス: active
- 作成日: 2026-11-27
- 対象: 登録とログイン(ログイン状態が無効になった接続を閉じること。RL-18、RL-19)。[ADR-005](ADR-005-layer-structure.md)「型参照の範囲」の規約を、補う

## Context

ADR-005 は、ポートを実装する adapter が domain を使う範囲を、型の受け渡しと、保管先の表現からの組み立てに限り、domain の規則(検証、判定)を、adapter から呼ばないと定めています。例外は、adapter のテストが、入力を用意するために、値を作る関数を呼ぶことの、1つです。この区別は、import の検査では検出できず、規約として、レビューで確かめています。

本スライスは、期限に達したログイン状態による接続を閉じ、配信の時点で期限を過ぎた接続には、届けません([ADR-014](ADR-014-authentication-method.md)、RL-18)。

- 接続と、ログイン状態の対応付けは、配信の adapter が保持する状態である(ADR-014、RL-39)。usecase は、どの接続があるかを、知らない。
- したがって、「この接続のログイン状態は、ある時刻に有効か」を、接続ごとに確かめる処理は、配信の adapter の中で行うことになる。時刻は、usecase が、ポートの引数で渡す。
- 有効かどうかの判定(時刻が、期限より前であること)は、domain のログイン状態が持つ。同じ判定は、保管先の問い合わせの条件にも現れる([ADR-016](ADR-016-login-state-and-counter-stores.md))。

本ADRは、配信の adapter が、この判定を、どの形で行うかを決定します。詳細設計のレビュー(2026-11-27)で、設計が、規約と合わない形になっていることに気付きました。ADR-005 は frozen であるため、本ADRに記録します。

## Decision

- ポートを実装する adapter は、次の条件をすべて満たす場合に限り、domain の判定を呼んでよい。
  1. adapter が保持する状態(1つのサーバーの中だけで保持する状態)の、要素ごとに、判定が要る。usecase は、その要素を知らず、代わりに判定できない。
  2. ポートの操作が、その判定を行うことを、ユースケースの用語で定めている(「ある時刻に、期限を過ぎたログイン状態による接続を閉じる」など)。
  3. 呼ぶのは、既にある domain の値についての問いであり、値を作る関数(検証)ではない。判定に要る値(時刻など)は、ポートの引数で受ける。
- 本スライスで当たるのは、1つである。配信の adapter が、保持するログイン状態について、有効かどうかの判定を呼ぶ。
- 当たる箇所は、置き場所ごとの指示(`.claude/rules/server.md`)に列挙する。列挙にない呼び出しは、これまで通り、行わない。加える場合は、上の条件を、レビューで確かめる。
- 値を作る規則(本文、送信の識別子、連絡先などの検証)は、これまで通り、adapter の実装から呼ばない。
- 保管先の問い合わせが、同じ判定を、条件として書くことは、本ADRの対象ではない。[ADR-012](ADR-012-transaction-boundary.md) が、行のロックと一意性の制約について定めたのと同じく、adapter の中の、実現の手段である。

## 検討した代替案

| 代替案 | 採らなかった理由 |
|---|---|
| 配信の adapter が、保持した期限と、渡された時刻を、自分で比べる | 規約の文言を、変えずに済む。判定の境界(期限ちょうどの時刻を、有効とするかどうか)が、domain、保管先の問い合わせ、配信の adapter の、3箇所に分かれる。配信の側だけが食い違うと、期限ちょうどに、操作は拒否されるのに、配信は届く。domain の関数を呼ばないだけで、判定を adapter が行うことは、変わらない |
| usecase が、接続の一覧をポートから得て、判定し、閉じる接続を指定する | 判定が、usecase に残る。接続の状態を、ポートの外へ出すことになり、状態を adapter の中に置く形(RL-39)が崩れる。一覧を得てから閉じるまでの間に、接続が増減する。配信では、送信のたびに、宛先の接続を、usecase が調べることになる |
| 接続ごとに、期限までの時間の経過を待ち、期限に閉じる | 配信の時点の判定が、要らなくなる。期限が、時間の経過で定まるため、テストから時刻を進めて、確かめられない(ADR-016 の Consequences)。接続の数だけ、待つ処理が増える |
| 規約を改め、ポートを実装する adapter から、domain の判定を、一般に呼んでよいとする | 条件を確かめる手間が、要らない。domain の規則を、application を経由せずに使う経路が、規約の上でも開く。現に要るのは、1箇所である |

## Consequences

- 規約の例外が、1つ増える(合わせて、2つ)。import の検査では、検出できない。指示の列挙と、レビューで確かめる。実装のときに、`.claude/rules/server.md` の規約と、確かめる手順を直す。
- 有効かどうかの判定は、domain と、保管先の問い合わせの、2箇所に残る。食い違いは、期限の直前と、期限ちょうどの時刻を使う、サーバーの振る舞いのテスト(RL-16、RL-18)で検出する。
- 条件の1は、状態を adapter に置くこと(PERF-3)の帰結である。後続のスライスが adapter に置く状態(プレゼンスなど)でも、同じ形が生じうる。その時点で、条件を確かめて、列挙に加える。先行しては、加えない。
- 観察記録に残す(OBS-024)。
