# ADR-021 出来事の記録を行う層

- ステータス: active
- 作成日: 2026-11-27
- 対象: 登録とログイン([仕様](../specs/registration-and-login.md)「記録」、RL-32、RL-33)

## Context

本スライスから、出来事の記録(R-6、OPS-3)を適用します。記録する出来事は、登録の申し込みと完了、ログインの成功と失敗、ログアウト、認証の拒否、上限の超過、エラーです。項目は、発生時刻、出来事の種類、利用者の識別子(特定できた場合)、送信元です。上限の超過には、数える単位の種類を添えます(仕様「記録」)。

これまでの形は、次の通りです。

- ウォーキングスケルトンが記録したのは、エラーだけである。ユースケースを呼ぶ adapter が、ユースケースが返した、拒否でないエラーを、1箇所で受けて、ログに出力している。
- application は、ログの標準ライブラリを import できない([ADR-005](ADR-005-layer-structure.md))。ログは、adapter と main が出力する。

判断に関わることは、次の通りです。

- 記録する項目のうち、利用者の識別子と、数える単位の種類は、usecase だけが知る。ユースケースを呼ぶ adapter は、資格を渡すだけであり、利用者を知らない([ADR-019](ADR-019-login-state-verification-layer.md))。
- 完了した操作の記録(ログインの成功、登録の完了、ログアウト)は、拒否でも、エラーでもない。記録する項目は、ユースケースの出力にも現れない。
- ユースケースを呼ぶ adapter は、2つあり(HTTP の操作を受けるもの、接続を受け付けるもの)、互いに import できない(ADR-005)。
- 秘密、資格、連絡先、識別名、表示名、本文は、記録しない(RL-33)。

本ADRは、出来事の記録を、どの層が行うかを決定します。詳細設計のレビュー(2026-11-27)で、詳細設計の判断(DD-16)を、本ADRに移しました。エラーを記録する箇所が変わり、層の分担に関わるためです。

## Decision

- 出来事の記録は、usecase が、記録のポートを呼んで行う。ポートを実装する adapter が、ログに出力する。application は、引き続き、ログの標準ライブラリを import しない。
- 記録する出来事と項目は、domain の型で表す。記録しないと定めたものは、その型に、項目を置かない。
- ユースケースを呼ぶ adapter は、ユースケースが返した拒否とエラーを、ログに出力しない。応答に置き換えるだけとする。
- エラー(操作を完了できなかった)の記録を、取りこぼさないために、ユースケースの公開する操作は、すべて、usecase の中の、共通の1箇所を通す。拒否でないエラーを返すときは、そこで記録する。形は、詳細設計で定める。
- ユースケースを通らない失敗(応答と、接続への書き込みの失敗、起動と終了)は、これまで通り、adapter と main が出力する。
- 記録のポートは、エラーを返さない。記録の失敗は、操作の結果を変えない。

## 検討した代替案

| 代替案 | 採らなかった理由 |
|---|---|
| ユースケースを呼ぶ adapter が、すべての出来事を記録する(これまでの形を広げる) | エラーを、adapter の1箇所で受けられ、取りこぼさない。採らなかった理由は3つある。(1) 拒否、エラー、完了の出力に、記録のためだけの項目(利用者の識別子、数える単位の種類)を載せて、返すことになる。(2) 利用者の識別子は、応答に載せない値であり、出力に加えると、通信の形式へ向かう経路に乗る(ADR-005 が、出力に domain の型を返さない理由と、同じである)。(3) 同じ記録の処理が、互いに import できない、2つの adapter に要る |
| エラーだけを adapter が記録し、そのほかの出来事を、usecase が記録する | エラーの取りこぼしがなく、adapter の変更が小さい。記録が、2つの層に分かれ、項目の形(送信元、利用者の識別子)を、2箇所で揃えることになる。エラーに、特定できた利用者を添えるには、エラーに項目を載せて、返すことになる |
| application が import してよい先に、ログの標準ライブラリ(log/slog)を加える | ポートが要らない。入出力を行うパッケージであり、ADR-005 の規則に反する。usecase のテストで、記録を、差し替えた実装によって、確かめられなくなる |
| ユースケースを包んで記録するものを、usecase の外(main、adapter)に置く | 各ユースケースが、記録を意識しなくて済む。ユースケースを呼ぶ側に、インターフェイスを置くことになる(ADR-005 が、採らなかった形である)。利用者の識別子と、数える単位の種類は、やはり、内側から返すことになる |

## Consequences

- 境界要素が、1つ増える(出来事を記録するポート)。domain に、出来事を表す型が加わる。観察記録の計数の対象とする([ADR-008](ADR-008-observation-records.md))。
- 記録する出来事と項目を、usecase のテストで、差し替えた実装によって、確かめられる。
- エラーを記録する箇所が、adapter の1箇所から、usecase の中に移る。共通の1箇所を通さない操作を加えると、そのエラーは、どこにも記録されない。import の検査では、検出できない。規約とし、操作ごとに、ポートを失敗させて、記録されることを確かめるテストを置く。実装のときに、置き場所ごとの指示(`.claude/rules/server.md`)に加える。
- 同じ指示の「application は、ログを出力しない」は、「ログの標準ライブラリを使わず、記録は、ポートを通す」に書き直す。
- HTTP の操作を受ける adapter は、ログの出力先を、受け取らなくなる。接続を受け付ける adapter は、接続への書き込みの失敗を出力するため、受け取り続ける。
- 記録に添えるエラーの文言は、usecase を通る。ポートを実装する adapter は、行の内容や、宛先を含まない形に作り直したエラーだけを、返す。保管先の adapter の規約を、本スライスで加える adapter にも、適用する(RL-33)。
- ユースケースの操作が増えるたびに、記録の手順が加わる(ADR-019 の、確認の手順と同じである)。
- 発生時刻は、記録を出力する時点の、サーバーの時刻である。
- 観察記録に残す(OBS-023、OBS-025)。
