# ADR-007 ローカルの開発環境の構成

- ステータス: frozen
- 作成日: 2026-11-19
- 対象: ウォーキングスケルトン([仕様](../specs/walking-skeleton.md)「技術要素の決定」)

## Context

ウォーキングスケルトンは、開発者の端末の上の、ローカルの開発環境でのみ動かします(仕様 WS-D6)。仮のログイン(WS-P2)は、誰でも任意の固定ユーザーとして振る舞えるため、ローカルの開発環境の外から到達できてはなりません。

選定の条件は、次の通りです(仕様「技術要素の決定」)。

- 秘密をリポジトリに含めずに、手順に従って起動できる(SEC-6)。
- すべての選定に共通する条件を満たす。

関連する受け入れ基準は、次の通りです。

- 依存物の版が固定され、リポジトリに記録されている(WS-32)。
- リポジトリとその履歴に、秘密が含まれない。秘密は、リポジトリの外から与える。確認方法は、機械的な検出による検査とする(WS-34)。
- 完了を示したメッセージは、サーバーと保管先を再起動した後も、履歴として読める(WS-08)。

動かすものは、サーバー(Go)、クライアント(Vite でビルドする静的なファイル)、保管先(PostgreSQL)です([ADR-001](ADR-001-language-and-libraries.md)、[ADR-004](ADR-004-data-store.md))。

## Decision

- 保管先(PostgreSQL)は、Docker Compose で、コンテナとして動かす。イメージの版は、定義の中で固定する。データは、コンテナを作り直しても残る場所(ボリューム)に置く。
- サーバーと、クライアントの開発用のサーバー(Vite)は、開発者の端末の上で、直接に動かす。
- サーバー、クライアントの開発用のサーバー、保管先は、いずれも、端末自身からの接続だけを受け付けるアドレス(127.0.0.1)で待ち受ける。
- ブラウザは、クライアントの開発用のサーバーにアクセスする。開発用のサーバーは、HTTP の操作と WebSocket の接続を、サーバーへ中継する。これにより、ブラウザから見たオリジンは、1つになる。
- 秘密(保管先への接続情報)は、リポジトリが追跡しないファイル(`.env`)で与える。リポジトリには、値を含まない見本(`.env.example`)だけを置く。保管先の定義とサーバーは、秘密が与えられていない場合、既定の値で動かず、起動に失敗する。
- 秘密の機械的な検出には、gitleaks を使い、リポジトリの履歴の全体を対象に実行する。
- 開発に使う道具(コード生成、検査、テスト)の版も、リポジトリに記録して固定する。
- 起動、コード生成、検査、テストの手順は、Makefile にまとめ、手順書(リポジトリの README)から参照する。

開発者の端末に要るものは、Go、Node.js、Docker(Docker Compose を含む)、make です。Docker は、Docker Compose の定義を実行できれば、提供の形(Docker Desktop、Docker Engine)を問いません。開発者の端末での形は、Consequences に記載します。

### 選定の条件の確認

| 条件 | 確認 |
|---|---|
| 秘密をリポジトリに含めずに、手順に従って起動できる(SEC-6) | 秘密は、追跡しないファイルで与える。手順は、見本をコピーし、値を決めて、起動することである。既定の秘密を持たないため、追跡するファイルに、秘密が現れない |
| 依存物の版が固定されている(WS-32) | Go と npm の依存物は、ADR-001 の通り。保管先のイメージ、開発に使う道具の版も、リポジトリに記録する |
| ローカルの開発環境の外から到達できない(WS-D6) | すべて、127.0.0.1 で待ち受ける |
| ライセンスが、MITライセンスでの公開と両立する | gitleaks(MIT)。開発の時点で実行する道具である |
| 個人データとメッセージを、外部のサービスへ送信しない(PRV-3) | すべて、開発者の端末の上で動く |
| 検証にかける費用を、小さく抑えられる | すべて無償で使える。開発者の端末で使う Docker Desktop は、個人の利用では無償である(利用条件は、組織の規模によって異なる)。保管先の定義は、Docker Desktop に依らず、Docker Engine でも動く |

## 検討した代替案

| 代替案 | 採らなかった理由 |
|---|---|
| サーバーとクライアントも、コンテナで動かす | 端末に要るものが、Docker だけになる。採らなかったのは、変更を反映して確かめるまでの時間が延び、デバッグの手間が増えるためである。開発者は1名であり、端末の間で環境を揃える必要が小さい。設置環境の構成(OPS-1)は、フェーズ1で定める |
| PostgreSQL を、端末に直接に導入する | Docker が要らない。版の固定と、作り直しが、手順に依るようになる |
| WSL2 の中に、Docker Engine を直接に導入する(Docker Desktop を使わない) | Docker Desktop の起動と、利用条件の確認が要らない。採らなかったのは、開発者の端末に Docker Desktop が既にあり、導入と更新の手間が増えないためである。保管先の定義は、どちらでも動くため、後から切り替えられる |
| 開発用の決まった秘密を、定義に書いておく | 手順が1つ減る。ローカルでしか使わない値であっても、機械的な検出は、本物の秘密と区別できない。秘密を追跡するファイルに書く形を、最初から作らない |
| ビルドしたクライアントを、サーバー(Go)から配信する | 開発用のサーバーと中継が要らない。変更のたびにビルドが要り、開発の速さが落ちる。静的なファイルを何が配信するかは、設置環境の構成(OPS-1)とともに、フェーズ1で定める |
| サーバーとクライアントを別のオリジンとし、CORS で許可する | 中継が要らない。サーバーが、他のオリジンを許可する設定を持つことになり、第三者のサイトからの操作を拒否する確認(WS-29)が、複雑になる |
| 手順を、他の道具(Task、just など)にまとめる | 記述は読みやすい。make は、多くの端末に既にあり、道具が増えない |

## Consequences

- 動作検証では、開発者の端末の上の、互いに状態を共有しない3つのブラウザから、同じアドレス(localhost)にアクセスする(仕様「動作検証」)。
- ブラウザは、localhost を、保護された文脈として扱う。保護された文脈でだけ使えるAPI(送信の識別子の生成に使う。[ADR-009](ADR-009-send-identifier.md))は、暗号化しないローカルの開発環境でも使える。端末のアドレスを指定してアクセスすると、使えない。
- サーバーが検証するアプリのオリジン([ADR-002](ADR-002-realtime-communication.md))は、設定で与える。ローカルの開発環境では、クライアントの開発用のサーバーのオリジンとする。開発用のサーバーは、Host ヘッダーを書き換えずに中継するため、サーバーが検証する Host(ADR-002)は、このオリジンのホストになる。
- 保管先のログの設定([ADR-004](ADR-004-data-store.md)「ログに本文を記録しない構成」)は、保管先の定義に含める。
- 自動テストは、この環境の PostgreSQL を使う([ADR-006](ADR-006-automated-testing.md))。サーバーのテストと、E2Eテストは、その上に、開発用とは別のデータベースを作って使う。保管先への接続情報は、データベースを作れる権限を持つものとする。
- 依存規則と飛ばし禁止の検査の手順は、違反を検出したとき、その出力を、記録用のファイルに追記する([ADR-008](ADR-008-observation-records.md))。
- 開発者の端末は、Windows の上の WSL2 である。サーバーと、クライアントの開発用のサーバーは、WSL2 の中で動く。Docker は、Windows の側の Docker Desktop を、WSL との連携によって、WSL2 の中から使う。WSL2 の中に、Docker Engine は導入しない。
- 保管先のコンテナは、Docker Desktop の側で動く。127.0.0.1 に限って公開したポートは、WSL2 の中と、Windows の側の、両方の 127.0.0.1 に現れる。WSL2 の、他のアドレスからは届かない(2026-11-21 に確かめた。Windows の側の、他のアドレスからは、確かめていない)。Docker Desktop を起動していない間は、保管先と、保管先を使うテストを、動かせない。
- ブラウザを Windows の側で動かす場合、ブラウザは、WSL2 の中の 127.0.0.1 で待ち受けるサーバーに、localhost でアクセスすることになる。これが成り立つことを、実装の最初に確かめる。成り立たない場合に、WSL2 のアドレスを指定してアクセスする構成にすると、待ち受けるアドレスの限定と、保護された文脈(上記)の両方が崩れる。その場合は、本ADRを改める。
- 通信経路の暗号化(SEC-2)と、設置環境の構築(OPS-1)は、フェーズ1から適用する。本ADRの構成を、AWS上の検証環境に、そのまま使わない。
