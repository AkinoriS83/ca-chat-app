# ADR-011 送信に使われた端末を、配信の宛先から除く手段

- ステータス: active
- 作成日: 2026-11-19
- 対象: ウォーキングスケルトン([仕様](../specs/walking-skeleton.md)「リアルタイムの配信」「後続に送る事項」)

## Context

仕様は、配信の宛先を、会話の参加者がアプリを開いている端末のうち、送信に使われた端末を除く、すべてと定めています(仕様「リアルタイムの配信」、WS-37)。送信に使われた端末には、完了の応答によって、メッセージを示すためです。送信者の他の端末は、宛先に含みます(WS-03)。

仕様は、除く手段を、設計で定めるとしています。

送信は HTTP で、配信は WebSocket で行います([ADR-002](ADR-002-realtime-communication.md))。サーバーは、送信の要求だけからは、それが、どの WebSocket の接続と同じ端末から来たのかを、知ることができません。

ここでの「端末」は、WebSocket の接続を1本持つ単位、すなわち、ブラウザの1つのタブです。同じブラウザの2つのタブは、別の端末として扱います。

## Decision

- サーバーは、WebSocket の接続ごとに、推測できない、接続の識別子を発行する。識別子は、受信を開始できたことの知らせ([ADR-010](ADR-010-message-ordering.md))に含めて、その接続で端末に伝える。
- クライアントは、送信の要求に、自分の接続の識別子を添える。
- サーバーは、配信のとき、送信者の接続のうち、識別子が一致する接続を、宛先から除く。一致を調べる範囲は、送信者自身の接続に限る。
- 識別子が添えられていない場合と、一致する接続がない場合は、何も除かずに配信する。送信は、拒否しない。
- サーバーは、識別子を、一致の比較にだけ使う。解釈せず、保管しない。
- 識別子は、ユースケースの入力として受け取り、配信のポートに、除く接続として渡す([ADR-005](ADR-005-layer-structure.md))。除く処理は、接続を保持する側(配信のポートの実装)が行う。

## 検討した代替案

| 代替案 | 採らなかった理由 |
|---|---|
| 送信を、WebSocket の上で行う | 送信に使われた端末が、接続そのものとして分かり、識別子が要らない。操作を HTTP に揃える判断(ADR-002)に反する |
| 除かずに配信し、クライアントが重複を除く | サーバーの手段が要らない。クライアントは、連番によって重複を除く仕組みを、既に持つ(ADR-010)。採らなかったのは、仕様が、送信に使われた端末を宛先に含めないと定めているためである(WS-37) |
| クライアントが作った端末の識別子を、接続の確立と、送信の両方に添える | サーバーからの伝達が要らない。サーバーが、クライアントの作った値の形式と、接続の間の重複を、扱うことになる。受信を開始できたことの知らせは、ADR-010 のために既にあり、そこに含めれば足りる |
| ブラウザが自動で送る情報(Cookie)で、端末を識別する | クライアントが、何も添えなくてよい。同じブラウザのタブが、同じ端末として扱われる。あるタブから送信したメッセージが、別のタブに配信されなくなる |
| 識別子の形式が正しくない送信、一致する接続がない送信を、拒否する | 入力を、厳密に扱える。接続が切れた端末からの送信や、送り直しが、拒否されることになる。識別子は、比較にしか使わず、形式を持たせる必要がない |

## Consequences

- 一致を調べる範囲が、送信者自身の接続に限られるため、他の利用者の識別子を添えても、その利用者への配信を止めることはできない(AC-6)。識別子は推測できず、他の利用者には伝わらない。
- 接続の識別子は、仕様の拒否の表(仕様「メッセージを送る」)に、新しい場合を加えない。添えられた値が、どの接続とも一致しなければ、何も除かないだけである。値の長さは、要求の全体の大きさの上限で抑える。
- 送信の完了の応答が端末に届かなかった場合、その端末には、配信も届かない。その端末では、送り直すか、会話を開き直すまで、送信できなかったメッセージとして示される。これは、仕様が帰結として認めている(WS-D2)。
- 接続が切れた端末から送信した場合など、除く接続が定まらないときは、送信者の他の端末を含む、すべての宛先に配信する。仮に、送信に使われた端末にも配信が届いた場合、クライアントは、連番によって、1通だけを示す(ADR-010)。
- 送り直しによって、保管済みのメッセージについて完了を示す場合は、配信しない([ADR-009](ADR-009-send-identifier.md))。除く処理は、行われない。
- 複数サーバー構成では、サーバーの間で中継する内容に、除く接続の識別子を含める。各サーバーは、自分が保持する接続について、除く処理を行う。接続の識別子は、サーバーをまたいで一意である必要があり、推測できない乱数による値は、これを満たす(PERF-3)。
- 「配信されない」こと(WS-37)は、送信者の2つの接続を使うサーバーのテストで確かめる([ADR-006](ADR-006-automated-testing.md))。
