# ADR-017 よく使われる秘密の一覧

- ステータス: active
- 作成日: 2026-11-27
- 対象: 登録とログイン([仕様](../specs/registration-and-login.md)「技術要素の決定」)

## Context

仕様は、よく使われる秘密の一覧にある秘密を、受け付けないと定めています(仕様「入力の規則」、RL-D3、RL-06)。一覧は、設置環境の中に持ち、外部のサービスへは問い合わせません(RL-D3)。本ADRは、一覧の出所と、持ち方を決定します。

選定の条件は、次の通りです(仕様「技術要素の決定」)。

- 外部のサービスへ問い合わせずに、照合できる(RL-37)。
- 件数が、OWASP ASVS 5.0.0 6.2.4 の求めを満たす。6.2.4 は、アプリの秘密の条件(長さの下限など)を満たすものから、上位3,000件以上と照合することを求めている。
- ライセンスが、MITライセンスでの公開と両立する。
- すべての選定に共通する条件を満たす。

秘密の長さの下限は、15文字です(仕様「入力の規則」)。公開されている一覧の多くは、短い秘密が中心であり、15文字以上のものは、わずかです。出所は、15文字以上のものを、3,000件以上含む必要があります。

候補の件数は、2026-11-27 に、SecLists のコミット 01bd31a(2026-11-26)の `Passwords/Common-Credentials/` のファイルを取得し、15文字以上、128文字以下の行を数えて、確かめました。

| ファイル | 全体の件数 | 15文字以上、128文字以下 |
|---|---|---|
| `100k-most-used-passwords-NCSC.txt` | 99,840 | 331 |
| `Pwdb_top-1000000.txt` | 1,000,000 | 5,406 |
| `xato-net-10-million-passwords-dup.txt` | 755,995 | 1,961 |
| `xato-net-10-million-passwords-1000000.txt` | 1,000,000 | 10,908 |
| `xato-net-10-million-passwords.txt` | 5,189,454 | 141,033 |

`xato-net-10-million-passwords` で始まる3つは、同じデータ(漏えいした、約1,000万件の利用者名と秘密の組)から作られています。`.txt` は、重複を除いた秘密を、現れた回数の多い順に並べたものです。`-dup.txt` は、そのうち、2回以上現れたものです。`-1000000.txt` は、先頭の100万件です(`.txt` の先頭の100万行と一致すること、`-dup.txt` が、末尾の1行を除いて、`.txt` の先頭と一致することを、確かめた)。したがって、`-1000000.txt` の、およそ75万6千件目から後は、1回だけ現れた秘密であり、その中の順は、回数を表しません。

## Decision

- 出所は、SecLists(danielmiessler/SecLists)の `Passwords/Common-Credentials/xato-net-10-million-passwords-1000000.txt` とする。取得するコミットを固定する(01bd31a91d11025e37c776b01edfe61c58dba784)。
- このファイルから、15文字以上、128文字以下の行を、すべて取り出したもの(10,908件、約190KB)を、一覧とする。件数で、さらに絞ることは、しない。
- 一覧のうち、元のデータに2回以上現れたものは、1,961件である。残りの 8,947件は、1回だけ現れたものである。2回以上現れたものだけでは、ASVS 6.2.4 の件数に届かないため、出所が区切りとしている、先頭の100万件までを取る。
- 一覧は、取り出した後のファイルを、リポジトリに含める。取り出す手順は、スクリプトとして、リポジトリに置く。サーバーは、一覧を、ビルドの時点で実行ファイルに含め、起動の時点でメモリに読み込む。実行時に、外部から取得しない。
- 照合は、入力された秘密と、一覧の値の、完全な一致で行う。秘密は、入力された通りに扱う(RL-D3)。
- 一覧は、ポートの背後に置く。domain と application は、ファイルを読む標準ライブラリを import できないためである([ADR-005](ADR-005-layer-structure.md))。
- 一覧を、定期的に更新する仕組みは、持たない。更新するときは、コミットを指定し直して、取り出し直す。

置き場所、スクリプト、ポートの形は、詳細設計で定めます。

### 選定の条件の確認

| 条件 | 確認 |
|---|---|
| 外部のサービスへ問い合わせずに、照合できる(RL-37) | 一覧は、実行ファイルに含まれる。照合は、サーバーのメモリの中で行う |
| 件数が、ASVS 6.2.4 の求めを満たす | 長さの条件を満たすものが、10,908件ある。現れた回数の順で、上位に当たるもの(2回以上現れた 1,961件)を、すべて含む。3,000件までの残りは、1回だけ現れたものから取ることになり、回数の順としての「上位3,000件」は、このデータからは、定まらない。15文字以上の秘密が、複数の人に使われること自体が、少ないためである |
| ライセンスが、MITライセンスでの公開と両立する | SecLists は、リポジトリの全体を、MITライセンスで公開している。元のデータ(2015年に、Mark Burnett が公開した、利用者名と秘密の組)について、公開者によるライセンスの表明は、公開時のページの控えを調べた範囲では、見当たらなかった(2026-11-27)。一覧は、SecLists から取得したものとして、出所とライセンスを、ファイルとともに記載する |
| 後続フェーズの妨げにならない | 秘密の変更と再設定(UC-07、UC-04)でも、同じ一覧で照合できる |
| 個人データとメッセージを、外部のサービスへ送信しない(PRV-3) | 秘密も、秘密に由来する値も、外部へ送らない |
| 検証にかける費用を、小さく抑えられる | 無償で使える |

## 検討した代替案

| 代替案 | 採らなかった理由 |
|---|---|
| 漏えいした秘密を照合する、外部のサービスに問い合わせる | 一覧が、最も広く、更新も要らない。仕様が、採らないと定めている(RL-D3、PRV-3) |
| 漏えいした秘密の、要約の一覧を、取得して持つ(Have I Been Pwned の、取得できるデータなど) | 範囲が広い。要約だけが提供されるため、長さの条件で絞れず、全体(数億件)を持つことになる。設置と更新の負担が、想定規模に見合わない |
| NCSC が公開した、上位10万件の一覧 | 公的な機関が公開したものであり、出所が明らかである。15文字以上のものが、331件しかなく、ASVS 6.2.4 の件数を満たせない |
| `Pwdb_top-1000000.txt` | 条件を満たす(5,406件)。採用した一覧の方が、件数が多く、元のデータの公開の経緯が、文書として残っている |
| 2回以上現れたものだけを取る(`-dup.txt` から取り出す) | 「よく使われる」の根拠が、明らかである。1,961件であり、ASVS 6.2.4 の件数を満たせない |
| 出所の全体(約519万件)から取り出す | 141,033件になり、より多くの秘密を拒否できる。増える約13万件は、すべて、1回だけ現れたものである。件数の条件は、先頭の100万件までで満たせる。個人を指しうる値(氏名、連絡先の形の値)を、リポジトリに、さらに多く写すことにもなる |
| Probable-Wordlists | 複数の漏えいにまたがって、順位を付けている。ライセンスが、CC BY-SA 4.0 であり、取り出したものを、同じ条件で公開することが求められる。MITライセンスでの公開と、分けて扱うことになる |
| 上位3,000件だけを持つ | 一覧が小さくなる。3,000件は、求められる下限である。10,908件でも、約190KBであり、絞る理由がない |
| 一覧を、起動のたびに、外部から取得する | リポジトリに、一覧を含めずに済む。実行時に、外部から取得したデータを適用する仕組みになり、OWASP Top 10 の A08 が、該当に変わる(仕様「OWASP Top 10 の該当の確認」)。取得できない場合の扱いも、要る |
| 自前で、規則から作る(同じ文字の繰り返し、キーの並びなど) | 出所とライセンスの確認が要らない。実際に使われた秘密に基づかず、ASVS 6.2.4 の求めを満たすことを、示せない |

## Consequences

- 一覧にない秘密は、漏えい済みであっても、受け付ける(RL-D3 の帰結と同じ)。15文字以上の秘密は、もともと、よく使われる一覧に載りにくい。一覧が拒否するのは、数字やキーの並びを長くしたものなどに、限られる。
- 照合は、完全な一致であるため、一覧の値と、大文字と小文字だけが異なる秘密や、末尾に1文字を足した秘密は、受け付ける。
- 一覧の約8割(8,947件)は、元のデータに1回だけ現れた秘密である。「よく使われる」というより、「漏えいしたことがある」秘密に近い。これらと一致する秘密を、利用者が選ぶことは、まれであると考える(推測である)。
- 一覧は、漏えいした実際の秘密であり、個人を指しうる値を含む(`@` を含む値が、26件ある。1回だけ現れた値に、多い)。いずれも、出所で、既に公開されている値である。これらを、リポジトリに写すかどうかは、開発者のレビューで確かめる。除く場合は、取り出す手順に、条件を加える。
- 一覧のファイルを、リポジトリに含めても、秘密の機械的な検出([ADR-007](ADR-007-local-development-environment.md) の gitleaks)は、検出しなかった(2026-11-27 に、取り出したファイルに対して、v8.30.1 で確かめた。リポジトリの履歴に対する検査は、実装の中で確かめる)。
- 境界要素が、1つ増える(秘密が、よく使われる一覧にあるかを確かめるポート)。application のテストは、テスト用の実装に差し替える。
- サーバーの実行ファイルが、約190KB 大きくなり、起動の時点で、一覧をメモリに読み込む。
- 一覧は、古くなる。元のデータは、2015年のものである。更新の仕組みを持たないため(仕様「OWASP Top 10 の該当の確認」の A08)、雛形の利用者が、自らの判断で、取り出し直す。
- 取得するコミットと、取り出す条件を固定するため、同じ手順で、同じ一覧を作り直せる(WS-32)。
